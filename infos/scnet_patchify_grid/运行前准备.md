## 4. 冻结配置与就绪证据

在1500的中心runtime保存不可变 `input_release.json`。以下是字段示例，尖括号必须替换为实际核验值，不能原样提交：

```json
{
  "release": "production_v2",
  "run_id": "<RUN_ID>",
  "code_sha": "<40位已部署SHA>",
  "selected_models": ["<用户确认的GCM>"],
  "analysis_years": "2015-2060",
  "baseline_years": "2015-2024",
  "bcsd_root": "<BCSD_ROOT>",
  "outputs_real_root": "<V2 outputs实体目录>",
  "patch_manifest": {"path": "<真实绝对路径>", "sha256": "<文件SHA256>"},
  "land_plan": {"path": "<真实绝对路径>", "size": 0, "mtime_ns": 0},
  "models": {
    "<用户确认的GCM>": {"status": "ready", "evidence": "<完成证据文件绝对路径>", "evidence_sha256": "<文件SHA256>"}
  }
}
```

SHA256取文件原始字节；size/mtime_ns取 `Path.stat()`；真实路径取 `Path.resolve(strict=True)`。证据可以是上游报告或包含用户确认、时间、路径、覆盖范围的记录，不能伪造完成状态。选择多个模型时每个均须有记录。提交前缺项记dependency_blocked；冻结后不原地修改release，更换输入或范围使用新RUN_ID。
