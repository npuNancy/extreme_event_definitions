# 从 BCSD-v2 全网格极端事件生成全球场站极端事件

编制日期：2026-09-28。状态：已实现代码和本地验证，远程 pilot 正在运行，生产作业尚未提交。实际命令与运行契约见 [README](README.md) 和 [goal.md](goal.md)。

本轮按用户更新使用本目录 accounts.csv 的13个worker，汇总目录为 `/work/share/acp6varuz3/extreme_grid/stations_v2/`。实现将catalog、网格元数据、mapping打包为单个prepare作业，避免共享资产并发写入；共2,257个逻辑作业。

## 1. 交付目标与推荐选择

将已经识别好的格点事件标志映射到场站位置，形成四模式 × 三 SSP × 两技术的场站事件时间序列，覆盖输入的原生 2015–2060 时间轴，并提供每个场站对应格点、距离、有效性和来源文件的完整记录。

| 决策 | 推荐方案 |
|---|---|
| 科学输入 | `grid_v2/runtime/authoritative_index.json` 列出的 `signals_*.nc` |
| 空间转换 | 规则经纬网的最近格点，直接复制事件标志 |
| 主输出 | NetCDF4，`signal_<event>(time,station)`，int8、zlib、分块写入 |
| 缺测 | 保留 `-127`；零表示有效的无事件 |
| 时间 | 原样保留每模式、每技术的原生时间和日历 |
| 文件粒度 | model/SSP/source_patch/tech/原有时间段 |
| 全局发布 | 分片 NC + 场站目录 + 映射 + JSON 权威索引 |
| 生产任务粒度 | 默认一个 model/SSP/source_patch/tech 作业顺序处理其 10 个时间段，逐文件提交完成证据 |
| 多服务器 | 沿用 13 个 worker 的候选账号池；1500 只汇总；按实测 I/O 吞吐限制并发 |

数据流程只有：**输入冻结 → 场站目录 → 网格映射 → 事件抽取 → 审核与发布**。不读取 BCSD 气象变量，不重算 baseline、阈值或事件识别。`low_resource` 也直接抽取原结果。

## 3. 场站目录：先确定 station 的身份

### 3.1 去重和稳定标识

每个 SSP 分别读取 CSV，按技术拆分；同技术同位置在不同年份出现的记录合并成一个 station。保留原始行到 station 的关系和年度容量记录。

沿用现有 ID：

```text
lon = ((lon + 180) % 360) - 180
station_id = sha1(f"{scenario}|{tech}|{lon:.4f}|{lat:.4f}")[:20]
```

具体要求：

1. 验证必需列、有限坐标、纬度范围、整数年份、wind/solar 类型、有限非负容量；输出坏行清单，不使用现有 loader 的静默 drop/fillna 作为唯一验证。
2. 先用规范化后的原始坐标去重，再生成 ID；不同坐标若四位舍入后 ID 相同，报冲突，不能静默合并。
3. `(year,type,lon,lat)` 重复行需核查来源；本批数据按迁移记录应无重复键，重复不能自动双计容量。
4. ID 不含 model、patch、执行账号或年份。同一 SSP/tech 的四模式共享同一站点目录。
5. `station` 整数只是文件内序号。跨分片/模式连接使用 `station_id`，不依赖行序。

三份本地副本合计约 160.64 万个 SSP/tech/位置；这不是带实体电厂 ID 的电厂清单。正式数量由远程输入冻结后的目录构建结果决定。

### 3.2 容量与生效年份

沿用项目现有 construction-year 语义：`activation_year=min(year)`；快照容量为同址 `year <= snapshot_year` 的 `capacity_gw` 总和。当前年份只有 2030、2040、2050，原始记录应完整保留在 `capacity_rows_<ssp>.csv.gz`，不把第一条容量当成全期装机。

**主事件文件保存全部原生气候时段，不因 activation_year 改写事件标志。** 它表示“该位置的极端天气”，可用于气候基线比较。附上 `activation_year`，按投运状态计算暴露/损失时再应用 mask。投运前“未暴露”与气象上“无事件”含义不同。

若后续需要投运后视图，由读取函数组合 `year(time) >= activation_year`；不要生成一整套重复气象文件。容量加权及损失计算属于下游，抽取阶段不使用容量改变事件。

## 4. 格点 → 场站：最近邻的具体定义

### 4.1 为什么直接选最近格点

事件结果是离散的 `0/1/fill`。场站序列定义为：

```text
station_signal[event,t,s] = grid_signal[event,t,iy(s),ix(s)]
```

插值布尔值会得到 0.2、0.7 等没有既定事件含义的数字，再阈值化会引入新的事件定义。最近格点能保持原有识别结果、事件有效性和复合/低资源事件的一致性。

这里得到的是“所在最近网格代表的场站天气事件”；空间代表性仍受 0.1° 网格限制，不增加局地观测信息。

### 4.2 距离与确定性

默认方法命名为 `nearest_regular`：沿用项目的规则经纬轴最近邻，纬度取绝对差最小值，经度使用周期差值：

```text
delta_lon = abs(((grid_lon - station_lon + 180) % 360) - 180)
match_dist_deg = max(abs(delta_lat), delta_lon)
```

这个距离是经纬角度的 L∞ 距离，不是公里距离，也不宣称是球面测地最近邻。另行记录 haversine `match_dist_km` 用于质量报告，不用于更改默认映射。现有 0.1° 场站位置预计多为精确命中，实际比例由 mapping 阶段给出。

默认兼容门槛 `max_distance_deg=0.15`，写入映射身份。正常完整 0.1° 网格的最近轴差应约不超过 0.05°；额外报告 `≤1e-6°` 精确命中、`≤0.05°`、`0.05–0.15°`、超门槛数量。较远匹配需追查边界/缺 patch，不能用放宽门槛隐藏覆盖问题。

等距时按规范化后的网格坐标 `(lat,lon)` 升序确定，再用 patch ID 做重复坐标的稳定排序；以数值容差 `1e-8°` 判断等距。排序用于选择，但保存原文件的实际行列索引，支持坐标升序或降序。

### 4.3 patch 边界与缺失 patch

采用“先选全局最近格点，再确定来源 patch”的顺序。不能先把站点截入一个 bbox，再限制只搜该 patch，否则边界附近可能错选。

实施步骤：

1. 从事件 NC 提取 lat/lon 轴和 `domain_mask`，结合当前 `runtime/patch_manifest.json` 建立小型空间索引；无需读取气象或旧 land_plan。
2. 检查网格间距、原点、轴方向及 patch core 边界。对已确认同源的规则网格，构建全局坐标轴和“坐标 → patch/local index”归属查询；稀疏缺 patch 的位置保留未覆盖状态。
3. 在完整规则格点几何上找最近坐标，再查该坐标是否属于本轮已有 patch。理论最近坐标位于缺失 patch 时标记 `NO_SOURCE_PATCH`，不能越过空白区吸附到另一个 patch。
4. 最近坐标可能落在站点几何 bbox 的相邻 patch，按该格点真实所属 patch 分配读取任务。分别保存 `station_patch` 与 `source_patch`。
5. 日期变更线按周期经度处理；bbox 使用西闭东开、南闭北开，北极端点单独纳入。共享坐标若出现重复，检查 core owner；身份不一致时报冲突。

若实际坐标不满足已假设的规则几何，停止该 grid group 的映射并报告，不能用名义 0.1° 硬套索引公式。每个来源 patch 在所有分片中的坐标必须一致。

### 4.4 最近格点无效时的处理

先按几何选格点，再查看该格点 `domain_mask`。最近格点的 `domain_mask=0` 时，保留该映射但标记 `OUTSIDE_DOMAIN`，场站事件全为 fill；不向内陆移动场站。若格点在域内但某事件某时刻缺测，只保留该事件该时刻的 fill，不随时间切换到另一个格点。

场站空间状态固定枚举：

| 状态 | 含义 | 主输出处理 |
|---|---|---|
| MATCHED | 有来源且门槛内、domain=1 | 原样复制 `0/1/fill` |
| OUTSIDE_DOMAIN | 最近来源格点 domain=0 | 保留 station，写 fill |
| TOO_FAR | 最近几何格点超门槛 | 目录登记，读取时重建 fill |
| NO_SOURCE_PATCH | 最近格点所属 patch 不在输入 | 目录登记，读取时重建 fill |
| INVALID_STATION | 坐标/字段非法 | 坏行报告，生产前解决或显式记为排除 |

全目录与每模式的覆盖表共同作为产物。没有来源的 station 不伪造 patch 文件，但全球读取器可按目录 reindex 补 fill，且保留原因。最终审核必须解释每一个目录 station 的去向。

### 4.5 映射复用

缓存键包含：规范化场站目录 hash、SSP、tech、各 patch 的坐标指纹、mask 指纹、patch manifest hash、匹配方法、门槛和映射实现版本。

相同空间几何可复用邻近位置；mask 不同仍需独立判有效性。不能因为都标称 0.1° 就默认四模式相同。当前样本空间指纹一致，完整网格确认后再合并缓存。地图建立一次，10 个时间段重复使用。

一个格点对应多个 station 时，读取一次唯一格点，再按映射广播到对应站点；输出仍保留每个 station_id。

## 5. 数据产品与保存形式

### 5.1 主产品：压缩的站点维 NetCDF

推荐主产品是“空间维压缩到 station”的 NetCDF4；它在存储语义上是规则的二维数组，**不是 COO/CSR 真稀疏矩阵**。优点是可直接由 xarray/netCDF4 读取、保留缺测语义并易于对接现有分析。

各站点共用同一时间轴时，CF 的 orthogonal multidimensional timeSeries 表达适合这种数据组织；设置 `featureType="timeSeries"`，`station_id:cf_role="timeseries_id"`。[CF timeSeries 规范](https://cfconventions.org/Data/cf-conventions/cf-conventions-1.9/cf-conventions.html#time-series-data)

建议 schema：

| 字段 | 维度 / 类型 | 语义 |
|---|---|---|
| time | time / 原始数值 dtype | 原样复制 units、calendar、数值 |
| station | station / int32 | 文件内索引，固定顺序 |
| station_id | station / 字符串 | 项目稳定 ID |
| lon, lat | station / float64 | 场站坐标，用于重算 ID，避免 float32 四位舍入漂移 |
| activation_year | station / int16 | 原始年度记录中的最早年份 |
| source_grid_lon, source_grid_lat | station / float64 | 选中网格坐标 |
| source_iy, source_ix | station / int32 | 来源 NC 的零基行列索引 |
| match_dist_deg, match_dist_km | station / float32 | 角距离门槛值与球面距离诊断 |
| mapping_status | station / int8 | MATCHED/OUTSIDE_DOMAIN 等枚举 |
| domain_mask | station / int8 | 选中格点的 domain 状态 |
| signal_事件名 | time,station / int8 | `0=no_event,1=event,_FillValue=-127` |

`source_patch` 放文件属性；`station_patch` 及全量容量明细放共享 catalog/mapping。事件变量的 `coordinates` 指向 station_id/lon/lat/activation_year 等辅助坐标；属性列表、flag_values 和标志类型按实际 NetCDF 类型写。

必要全局属性：`schema_version=station-extreme-v1`、model、scenario、tech、source_patch、analysis_years、source_collection_id、source_run_id、source_signal_identity、source_index_sha256、source_file、source_realpath、mapping_sha256、catalog_sha256、code_sha、match_method、max_match_dist_deg、activation_mask=off、supported_events、skipped_events、event_definitions、来源 baseline_identity 和原事件算法标识。

输入中不存在的事件不创建全零变量。`dust` 保留 skipped 原因。源事件定义和 baseline 只作为 provenance 引用，不要求打开 baseline NC。

### 5.2 Chunk、压缩和读取

输入样本 chunk `(240,32,32)`。输出 pilot 候选为 `(240,256)`、`(960,256)`、`(240,1024)`，实际各维取不超过维长的值；zlib level 比较 1 和 4，shuffle 开启。单变量一个候选 chunk 约 60–240 KiB。确定配置后整轮保持一致并写入 profile。

chunk 选择需兼顾按时间批量和按少量场站读取，缓存至少能容纳正在使用的源 chunk。具体性能取决于访问模式，应实测，不能由 CPU 数推断。[Unidata chunk 性能说明](https://docs.unidata.ucar.edu/nug/current/netcdf_perf_chunking.html)

源读取用 `mask_and_scale=False` 或 `set_auto_maskandscale(False)` 获取原始 int8，并显式检查取值集合。不能先解码 NaN 再直接转 int8。写出时 `_FillValue=-127`；用 xarray 默认读取得到 NaN 是正常解码行为，比较等价性时使用原始整数模式。

### 5.3 真稀疏 NC 是否值得做

初版优先完成可直接读取的压缩站点 NC。pilot 同时测事件比例 p、缺测比例 q、主 NC 压缩大小和两类读取时间；有明显空间收益才增加稀疏导出，不使其成为首轮前置依赖。

若选 COO，每个事件分别保存：

```text
event_time_index(obs), event_station_index(obs)       # 值隐含为 1
missing_time_index(missing), missing_station_index(missing)
time(time), station_id(station), 其他 station 元数据
```

完整域内、已覆盖位置的未列项解释为 0，missing 表恢复 -127。静态无效站点可用 mapping_status 压缩表达整列缺测，但 reader 必须显式实现。全无事件、全缺测、未匹配站点仍保留在 station 维和目录中。

两个 int32 索引约 8 字节/非零项，未经压缩的二维 int8 约 1 字节/元素；忽略元数据和静态 mask 优化时，COO 只有在 `8(p+q)<1` 才有原始字节优势。实际还要和 zlib 后的文件比较，不能用“事件稀少”直接承诺更省空间。obs 数量/偏移用 int64；索引超 int32 时升级。

稀疏文件不冒充 xarray 能自动展开的普通 timeSeries，需自有 schema、读写 round-trip 测试和增量 writer。若事件连续性强，可后续考虑记录连续区间，但缺测边界、分片边界及区间端点都需要独立契约。

### 5.5 全球访问和下游兼容

提供 `open_station_signals(index, model, scenario, tech, station_ids=None, years=None)`：先索引选源 patch，再按时间顺序打开需要的分片，按 station_id 返回所选站点，并携带有效性。缺来源站点根据 catalog 补 fill。跨 patch 合并之前检查同组合的时间轴一致；不默认打开四模式全部文件。

如需全球逐年统计，逐 patch/time chunk 累计即可，不先构建全球大数组。主交付不需要单一全球 NC。相同技术/模式内部可构造逻辑全期视图；跨模式及 wind/solar 不强制拼成一个共同 time 维。

现有损失脚本期待 `<model>/<ssp>/<patch>/<tech>.nc`，因此新分片不能直接替换旧目录。后续接入可选：让下游读本索引；或流式导出明确需求范围的 `<tech>.nc`。来源 patch 与旧几何 patch 不一致时按 station_id 重组，不能仅按 patch 文件名连接。

另一个明确兼容点：现有 `generation_loss/signals.py` 会将缺测转 False。接入前必须使其保留事件有效性、统计有效样本分母，并检查 CF 与事件的原生时间完全一致；仅改路径会丢失新数据的缺测语义。这是后续接口改动，不属于本次方案编写的实际代码修改。

## 6. 新增代码与复用边界

按照当前仓库布局，工作流文件放本目录，不另起一套通用框架。下列核心路径已实现；`station_contract.py`负责通用文件契约，`station_pipeline.py`负责准备、抽取、审核和发布编排：

| 文件 | 责任与主要接口 |
|---|---|
| `grid_extreme_signals/station_extract.py` | 读取已识别事件、按映射分块 gather、三态 writer、分片身份/完成检查 |
| `grid_extreme_signals/station_catalog.py` | CSV 验证、位置去重、稳定 ID、年度容量关联和覆盖统计 |

## 7. 抽取算法与 I/O 控制

任务按 `source_patch` 组织，让一个源文件集中服务该 patch 的所有场站。不能每站打开一次文件，也不能一次性 load `(全部时间,全部纬度,全部经度)`。

每个时间分片的执行：

1. 从冻结索引定位 stage=signals 的精确路径，验证 sidecar/文件身份、model/SSP/tech/patch/years 与映射相符。
2. 打开源 NC 一次，获取实际 chunk、维度顺序和事件列表；检查 time/坐标/domain 指纹，关闭自动 mask/scale。
3. 将唯一 `(iy,ix)` 按源空间 chunk 分组；station 排序按源 chunk、格点、ID 固定，记录反向映射。
4. 对每个时间 chunk、每个事件，读取需要的连续源空间块，在内存中用配对索引 `block[:,iy_local,ix_local]` gather；不对磁盘变量直接同时传两组离散数组，以免产生笛卡尔积或重复解压。
5. 使用有界 `(time_chunk,station)` 缓冲逐事件写出，或对超大 patch 改为输出 station block。一个变量写完后释放缓冲；没有选中格点的源 chunk 不读。
6. streaming 统计每事件每站的 event_count、valid_count、missing_count，验证值域和拷贝一致性；这些统计可写 sidecar 摘要及 audit 辅助文件。
7. 完成一个分片即原子提交，处理下一个源分片。失败只重做未完成文件，不重新打开已验收的 46 年输出。

源 chunk 的读取、gather、写入、压缩分别计时。多个事件逐一处理可降低内存；允许单作业少量进程处理互不相交的时间文件，但不能让多个进程同时写一个 HDF5 文件。初版单进程，先用账号/任务间并行获取吞吐。

内存近似由 `time_chunk × station_count × 当前并存事件数`、源块和 HDF5 cache 构成。以 240 × 400,000 × 1 byte 为例，单事件缓冲约 96 MB；若误解码 float64 会增加八倍。实际峰值仍需计入目录、索引、压缩缓冲和 Python 开销。

## 8. 多服务器分工与任务依赖

### 8.1 阶段图和任务数量

```text
冻结输入索引、CSV 身份、代码 SHA
              ↓
catalog（每 SSP） + grid metadata inventory
              ↓
mapping（每 SSP × tech × distinct spatial group）
              ↓
extract（model × SSP × source_patch × tech；内含各时间分片）
              ↓
audit（相同组合：全部分片、覆盖和抽取一致性）
              ↓
1500 发布 global index + coverage report
```

| 阶段 | 任务边界 | 依赖 | 完成证据 |
|---|---|---|---|
| catalog | 1 SSP，两技术 | 冻结 CSV | catalog、容量记录、坏行/重复检查、hash、receipt |
| mapping | SSP/tech/spatial-group | catalog、网格元数据 | mapping、覆盖表、identity、receipt |
| extract | model/SSP/patch/tech | 相应 mapping、全部源分片 | 每分片 NC+sidecar+receipt |
| audit | model/SSP/patch/tech | 该组合全部抽取分片 | audit JSON+receipt |
| publish | 整轮 | 所有组合审核、所有站点解释完毕 | 中心索引和覆盖总表 |

初始 catalog 为 3 个作业；grid inventory 可先用一个小型计算作业按代表文件读取各空间组。mapping 若全批空间契约相同为 6 个，实际按指纹分组确定；不能预先保证只有 6 个。

抽取组合上限 1,128，输出信号分片上限 11,280。无 station 分配到某来源 patch 的组合记 `SKIPPED_NO_STATIONS` 并出具范围/目录 hash 证据，不生成空 NC；其“跳过成功”与“有站但全缺测”分开。

默认一个抽取作业顺序处理一个组合的全部时间文件，逻辑分片 ID 为：

```text
station-v1/extract/<model>/<ssp>/<tech>/<source_patch>/<start>-<end>
```

Slurm job 是一个包含最多 10 个分片的执行包，调度台账同时记录包和分片。生产前据 pilot 决定是否将超时/重 patch 拆成单时间段作业；不能把同一分片同时放进两个活动包。

审核可独立作业（最多 1,128），也可在最后一个抽取包内串行执行以减少短作业开销；审核 receipt 仍单独记录。无全局 extract 屏障：某组合齐备即可审核。

### 8.2 账号与存储拓扑

候选账号直接引用 `accounts.csv`：13 个 worker + 1500 aggregator。实施时检查账号当前可用性、配额、分区和读取 ACL，再冻结本轮 allowlist；历史核时余额及上一轮分工不代表今天的资源。

同一 SCNet 共享文件系统下，“多个服务器”主要表现为多个账号的独立 Slurm 队列与计算节点。所有 worker 直接只读权威网格输入，只向自己的 share 运行根写结果；避免完整网格输入复制 14 份。

准备时每个 worker 验证：读取统一索引、解析软链接后的源文件、读取 station CSV/catalog/mapping、执行共享环境、写自身输出、汇总账号读取其产物、跨账号 lock/原子 rename 的实际语义。软链接不赋予权限。

若某服务器不共享该挂载，先从映射确定其需要的源分片清单，再按清单非破坏性复制 NC+sidecar 与共享资产；记录内容摘要、原始路径与本地缓存路径，验证完成后使用。传输成本单独测量，不能假定 SSH host alias 不同就需要复制，也不能只复制悬空软链接。

### 8.3 任务分配和并发

按 I/O 成本分配，而非平均 patch 数。初始权重取 `需要读取的源空间chunk数 × timechunk数 × 事件数`，再加预计输出大小；pilot 后替换为实测 elapsed/bytes。将最重组合依次分配给当前累计权重最低、余额充足的账号，支持空闲账号领取未开始组合。

每账号 account-wide active jobs 上限沿用 20，14 账号理论上限 280，其他项目作业也占槽。**280 是调度上限，不是本任务推荐起始并发。** 本任务可能受共享存储吞吐限制：pilot 从 2–4 个账号、每账号 1–2 个任务开始，按全局 8 → 16 → 32 → 64 逐步提高；吞吐不再增加或 I/O 延迟明显升高就停止扩容。

同一输入时间文件由一个任务读取，避免按事件拆任务造成反复打开与元数据竞争。稀疏 patch 可在一个包中顺序执行几个短组合；只有 pilot 证明调度开销显著时才增加这种打包配置。

### 8.4 初始资源 profile

| 阶段 | CPU / Python 进程 | 初始时限 | 备注 |
|---|---|---|---|
| catalog / mapping | 4 CPU / 1 进程 | 2 h | 百万位置用 searchsorted 分块，关注 pandas/映射峰值 |
| extract | 2 CPU / 1 进程 | 2 h | 十个分片顺序抽取；pilot 重 patch 超过约 90 min 则拆包或调整时限 |
| audit | 2 CPU / 1 进程 | 1 h | 已输出分片的坐标/时间/值域/抽取抽样 |

分区默认候选 `wzhctest`；每核内存按实际分区核实。若需要通过增加 CPU 获取内存，记录原因，不能把分配 CPU 数当作 Python 并行度。所有库线程初始设为 1，避免过量线程。

脚本使用既有环境：

```bash
source /work/home/acbpgywfpz/miniconda3/bin/activate climate
```

沿用现有 generator 对 activation hook/strict shell 的兼容方式。Slurm 参数含明确 CPU、时间、日志；`#SBATCH` 不展开 shell 变量，提交时显式 `--chdir=<worker share root>` 并预建日志目录。不自动使用 job arrays。

### 8.5 调度控制与断点续作

沿用项目共享提交锁协议，准备阶段确定其他工作流正在使用的锁，不能另建互不协调的锁后声称满足全账号上限。锁内执行“查询本账号全部 active → 领取任务 → 核对依赖和输入 → 提交 → 写 Job ID”；另有全局 unit claim 防止跨账号重复。

每轮控制执行：查询 squeue/sacct → 检查 receipt/产物 → 分类 → 更新 progress → 补槽/有限重试 → 记录下一轮时间。作业从 squeue 消失不等于成功；`submitting/unknown` 状态先查重，不立即重复提交。

失败处理：暂时性节点/I/O/超时故障最多自动重试 2 次；OOM 调低缓冲或新建资源 profile；输入身份、schema、坐标、权限等确定性错误暂停受影响任务链并报告。active 作业不改派；失败包中已经成功的分片可保留在原账号，后续包通过中心台账跳过，剩余分片写新账号自身目录。

默认不覆盖已完成产物。同分片若意外存在两个成功候选，比较输入与结果证据后由发布器确定唯一权威路径，不按“最新文件”自动选择。

部署顺序为本地实现/测试 → 明确 SHA → Git 提交推送 → 各账号 HTTPS clone 或干净 fast-forward pull → 生成脚本、bash -n → pilot → 分批生产。生成器不执行 SSH、sbatch 或科学计算。登录节点仅做轻量文件/JSON/调度操作；CSV 全量整理、NC 映射/抽取/审核均放计算节点。

## 9. 容量和时间预算

基于本地目录统计，三 SSP 的 wind 唯一位置合计 817,576，solar 合计 788,821。用每模式约 134,400 个三小时点估算：

```text
raw ≈ 4 models × 134400 × (817576 × 5 + 788821 × 6) bytes
    ≈ 4.74 TB = 4.31 TiB
```

这是保留所有这些位置、完整分析期、int8 的近似逻辑体积，未含坐标/sidecar，未扣除无来源站点；不是磁盘压缩后的预测。日历和技术导致精确时间长度不同，最终预算使用各输入的真实长度。

对密集/稀疏 patch、风/光和不同日历分别测实际压缩比。若压缩后与 raw 的比值分别为 1%、5%、10%，仅作为算例对应约 47、237、474 GB；这些不是本轮已测结果。

配额预算包含最终产物、活动临时文件、失败尝试、可选兼容导出、日志和共享资产，再留至少 30% 余量。临时文件通常只覆盖当前分片，不保留第二份全量结果。跨账号峰值分别计算，不能只看汇总账号余量。

全程时间按 pilot 的源 chunk 吞吐和压缩写出吞吐加权外推。报告 1/8/16/32 并发的总吞吐、单任务 p50/p95、MaxRSS、平均输出压缩比；不把已有格点事件识别耗时作为本抽取任务耗时。

## 10. 完成契约、测试和质量报告

### 10.1 单分片成功

同时满足：Slurm 成功/exit 0；原子完成 NC、sidecar、receipt；输入 index/catalog/mapping/code 身份一致；事件名、三态、station ID/坐标、时间轴、来源索引正确；文件大小和记录一致。

逐流块检查 `0/1/-127` 值域并生成统计。每事件必须满足 `event_count <= valid_count` 和 `valid_count+missing_count=time_count`。统计只比较同一事件，不能把互相重叠事件相加当作任何事件总数。

输入中的 missing 不可变成 0，也不可因 `value != 0` 变成事件。domain 外整列必须 fill；同源格点多站点在主文件中必须逐值相同。

### 10.2 组合与全球审核

每组合检查 10 个时间文件无重叠、按源时间顺序连续、站点 ID/顺序一致、日历和单位可解释。源首点缺 00:00 等已存在差异不人为判成失败或补齐，验收基准是源 time 的精确复制。

抽取正确性以本轮源事件为 oracle。pilot 对选定小块做全部逐元素比对；生产在写入时检查全部流块，并在独立 audit 中按固定种子抽取站点/时刻，覆盖每事件、每分片、日期变更线、边界和缺测样本。只做抽样的结论明确标注，不伪称对所有文件独立全量重读。

全球站点守恒：对每 SSP/tech/model，完整 catalog = 唯一 MATCHED + OUTSIDE_DOMAIN + TOO_FAR + NO_SOURCE_PATCH（合法目录行）；原始非法行另计。一个合法 station 在该 model/SSP/tech 中只能有一个来源归属，无重复、无静默消失。

覆盖报告至少含：源 CSV 行数、唯一 station 数、按 mapping_status 数量、按距离分箱数量、跨 patch 数、各事件有效/缺测率、空组合数、完成组合数。处理完成与有效数据覆盖分开报告；存在上游覆盖缺口时交付缺口表，不宣称 100% 有效覆盖。

### 10.3 必要测试矩阵

## 11. 实施顺序与交付清单

1. **冻结输入和目录口径。** 保存统一索引/manifest 快照和 hash，在计算节点核对远程 CSV hash 并构建 catalog；确认新输出根与原目录不同。产出 input_release、目录统计及覆盖任务清单。
2. **实现最小抽取闭环。** 先完成 schema、catalog、mapping、单分片 reader/writer 和必要单元测试；以小型合成输入验证三态、边界和恢复。
3. **真实 pilot。** 选择场站最密和较稀疏的来源 patch，至少各含 wind/solar、两类日历、缺测/边界样本。先单分片，再一个完整 10 分片组合。测 RSS、读取/写入耗时、压缩比和等价性。
4. **冻结生产 profile。** 决定输出 chunk/compression、分片或组合任务、实际 worker allowlist、并发 I/O 上限；据此生成 manifest/task_allocation，检查所有 shell 脚本。
5. **分批处理。** 从低并发开始，只提交依赖齐备任务；持续审核已完成组合并更新台账；输入身份或数据契约错误及时局部停止。
6. **统一发布。** 1500 建立唯一权威分片索引、catalog/mapping 入口和 coverage report；提供按 station_id/时间读取示例，记录全部已知覆盖缺口。

最终必需交付：站点信号分片、完整场站目录/年度容量源记录、模型相关映射与未覆盖清单、每组合审核、全局索引、运行 provenance、经过测试的读取接口及使用说明。
