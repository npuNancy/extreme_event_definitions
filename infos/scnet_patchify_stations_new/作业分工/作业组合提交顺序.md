本轮固定四个GCM、三Climate×三Station、两种tech、47patch，共3,384个科学unit。
prepare和publish另各1个作业；extract作业内包含审核。1872/acjpoxgsdu只汇总，不运行任何作业。

## 2. Ready queue顺序

1. 准备关卡全通过后，只提交一个prepare作业。
2. prepare验收后，模型顺序：CANESM5 → MPI-ESM1-2-HR → MRI-ESM2-0 → BCC-CSM2-MR。
3. 每模型中Climate顺序：ssp126 → ssp245 → ssp585。
4. 每Climate内Station顺序：ssp126 → ssp245 → ssp585，明确包含全部非对角配对。
5. 每配对内wind → solar；每tech内按land_points_reference从大到小，patch ID打破平局。
6. 所有extract及审核成功后，提交唯一publish。

生成manifest.jobs的extract顺序即上述顺序。每个model/Climate有3×2×47=282个unit；
每个model/Climate/Station有2×47=94个unit；每个model合计846个unit。

排序只是优先级，不是屏障：当前模型/Climate/Station没有安全ready候选时，立即从后续组合补槽，
不等整组94、282或846个任务全部完成。所有worker按账号跨项目活动数持续补足至20；
满额账号不再提交。依赖未就绪、账号不可观测、提交unknown、存储/权限阻塞时必须记录原因。

## 3. 强制重分配

初始owner有待提交任务时优先消化自己的ready队列；若某worker已用尽预分配任务但仍有空槽，
从其他worker的全局ready队列选择**尚未提交**的任务。候选账号按空槽数降序，平局轮询。
仍有后续ready任务时不能只等待繁忙owner释放槽位。

仅改变state.username，logical_owner不变；递增assignment_version，记录reassigned_from/at/reason和JobID。
不得移动已提交、PENDING、RUNNING、submitting或unknown任务；不得取消原Job后复制运行。
同一unit在一个时刻最多一个活动Job，脚本的14份副本共享同一科学身份、输出根和锁键。

重分配使用目标账号已经校验的同profile脚本。锁内重新核对所有活动作业数、任务claim与依赖，
先持久化submitting，再sbatch并立即登记JobID。SSH超时先按token查清是否已提交，不盲目补交。
普通重分配不重新运行生成器；资源变更需先在全部14账号准备新profile包。

提交锁、终态证据、重试上限和每15分钟执行顺序以[goal.md](../goal.md)为准。
