# 低资源事件接入代码修改计划

> 根目录：`/data6/yanxiaokai/project_climate/extreme_event_definitions`
>
> 本次修正目标：低资源事件阈值不得再用各模式、各 SSP 自身的 CF 序列计算。应先基于 ERA5Land 的 2015-2025 年风电/光伏 CF 计算固定低资源阈值并保存；后续跑不同模式、不同 SSP 时，只读取这套已保存阈值来判定 `signal_low_resource`。

---

## 1. 当前问题

1. 仓库已有低资源事件入口：
   - `registry.py` 注册了 `LOWRES = {"wind": wind_low_resource, "solar": solar_low_resource}`。
   - `events/wind_low_resource.py`、`events/solar_low_resource.py` 调用 `common.low_resource(...)`。
   - `grid_extreme_signals/cf_low_resource.py` 已能基于 CF 文件计算低资源信号。
   - `grid_extreme_signals/signal_runner.py` 和 `scripts/station_signals_direct.py` 已接入默认低资源计算。

2. 现有阈值计算逻辑不符合本次口径：
   - 当前 `compute_station_low_resource(...)` 会用当前任务对应的 CF 文件及其 `baseline_years` 直接计算气候态和 P5 阈值。
   - 这意味着 `NESM3/ssp126`、`NESM3/ssp585`、其他 GCM/SSP 都会得到各自的低资源阈值。
   - 该做法会把未来情景自身的气候分布当作阈值基线，导致不同模式/SSP 之间的低资源事件不可比。

3. 正确口径应改为：
   - 阈值来源固定为 ERA5Land。
   - 基线期固定为 `2015-2025`。
   - 阈值预先计算并落盘。
   - 之后所有模式、所有 SSP 只读取同一套 ERA5Land 阈值，不再在情景 CF 上重新估计阈值。

## 3. 低资源事件口径

### 3.1 变量口径

低资源统一使用容量因子 CF：

```text
wind:  wind_cf
solar: solar_cf
```

不再使用旧的气象资源口径：

```text
wind:  wind_ms
solar: rsds
```

输出属性必须明确：

```text
low_resource_source = capacity_factor
low_resource_threshold_source = ERA5Land
low_resource_threshold_baseline_years = 2015-2025
```

### 3.2 计算公式

对 ERA5Land 基线期内每个网格点 `k`，CF 序列记为 `CF(t,k)`。

1. 计算 24h 居中滚动均值：

\[
R(t,k)=\operatorname{mean}\{CF(\tau,k): \tau \in W_{24h}(t)\}
\]

ERA5Land CF 是小时级数据，因此：

```text
window_steps = 24
```

2. 计算月×小时气候态：

\[
C(m,h,k)=\operatorname{mean}\{R(t,k): month(t)=m,\ hour(t)=h,\ t \in 2015\text{-}2025\}
\]

3. 计算 ERA5Land 距平：

\[
A(t,k)=R(t,k)-C(month(t),hour(t),k)
\]

4. 计算每个 SSP 场站点的 P5 阈值：

\[
T(k)=P_5\{A(t,k): t \in 2015\text{-}2025\}
\]

5. 保存 `C(m,h,k)` 和 `T(k)`，后续不再重复估计。

### 3.3 后续模式/SSP 判定

对任意待计算的模式/SSP CF 序列 `CF_model(t,j)`：

1. 计算该模式/SSP 自身的 24h 居中滚动均值 `R_model(t,j)`。
2. 将场站 `j` 匹配到同 SSP 稀疏阈值文件中的 station `k`。
3. 使用 ERA5Land 的 `C(m,h,k)` 计算距平：

\[
A_{model}(t,j)=R_{model}(t,j)-C_{ERA5Land}(month(t),hour(t),k)
\]

4. 使用 ERA5Land 的 `T(k)` 判定低资源：

\[
signal\_low\_resource(t,j)=A_{model}(t,j)\le T_{ERA5Land}(k)
\]

注意：不同模式/SSP 只改变 `R_model`，不改变 `C_ERA5Land` 和 `T_ERA5Land`。

### 3.4 光伏夜间处理

光伏继续做夜间剔除，避免夜间 CF 为 0 时被系统性判为低资源：

\[
signal(t,j)=False,\quad solar\_elevation(t,j)\le 0
\]

夜间判断使用目标点位的经纬度和目标时间轴。

### 3.5 `t` 与 `t+1` 标记

保留现有低资源事件定义中的向后扩展一步：

```python
ev2[1:] |= ev[:-1]
```

输出属性写明：

```text
low_resource_mark_next_step = true
low_resource_timestep_hours = <target CF timestep>
```

ERA5Land 阈值预计算阶段是 1h；未来情景 CF 若为 3h，`t+1` 表示下一个 3h 时间步。

## 5. 代码修改计划

### 5.1 新增 SSP 场站稀疏 ERA5Land 阈值预计算脚本

新增脚本：

```text
scripts/precompute_station_low_resource_thresholds.py
```

职责：

1. 读取 `data/cfs/CFs_of_wind_ERA5Land` 和 `data/cfs/CFs_of_solar_ERA5Land` 的月文件。
2. 检查 `2015-01` 至 `2025-12` 文件是否齐全。
3. 读取 SSP 场站 CSV，按 `(lon, lat, type)` 去重，并记录 `activation_year=min(year)`。
4. 对每个场站选取四周 4 个 ERA5Land 网格点，计算双线性权重。
5. 按场站块读取 ERA5Land CF，不一次性读入完整 `(time, lat, lon)`。
6. 对四点加权后的场站级 ERA5Land CF 计算：
   - 24h 居中滚动均值；
   - 月×小时气候态 `clim(month,hour,station)`；
   - ERA5Land 距平；
   - P5 阈值 `threshold(station)`。
7. 写出 SSP + 技术类型拆分的稀疏阈值 NetCDF。

建议 CLI：

```text
--cf_root data/cfs
--stations_csv data/stations/stations_SSP1-2.6.csv
--scenario ssp126
--output_dir outputs/low_resource_thresholds/sparse_station_ERA5Land_2015-2025
--baseline_years 2015-2025
--tech both
--station_chunk 128
--allow_incomplete
```

默认不允许数据不完整。`--allow_incomplete` 只用于调试，正式结果不得使用。

### 5.2 修改 `grid_extreme_signals/cf_low_resource.py`

把当前“直接从任务 CF 估计阈值”的逻辑改为两阶段：

1. 新增稀疏阈值读取：

```python
load_sparse_low_resource_threshold(threshold_file)
```

读取：

```text
station_lat, station_lon, station_type, attrs
```

2. 新增目标点匹配稀疏阈值文件：

```python
match_sparse_threshold_stations(threshold, target_lat, target_lon, tech)
```

要求：

- 复用 `station_match.normalize_grid_lon(...)` / `lon_to_180(...)`。
- 按 `(lon, lat, type)` 匹配同一 SSP 场站。
- 不再对完整 ERA5Land 阈值网格做最近邻查找。

3. 修改场站低资源计算：

```python
compute_station_low_resource(..., threshold_file=...)
```

核心变化：

- 目标 CF 文件只用于计算 `R_model(t,j)`。
- `clim_tbl` 和 `thr` 来自 ERA5Land SSP 场站稀疏阈值文件。
- 不再使用目标 CF 的 `baseline_years` 估计阈值。

4. 保留兼容性：

- 可以保留旧参数 `baseline_years`，但只作为弃用兼容参数。
- 若未传 `threshold_file`，应报错或明确 warning 后走 legacy 行为；正式 pipeline 必须传 `threshold_file`。

### 5.3 修改 `tools/common.py`

当前 `tools.common.low_resource(...)` 已支持传入 `clim_tbl` 和 `thr`，但注释仍强调“便捷近似”。需要改成正式支持外部阈值：

1. 明确 `clim_tbl/thr` 可以来自外部基线。
2. 当传入 `clim_tbl/thr` 时，不使用 `base_mask` 估计阈值。
3. 继续支持：

```text
window_steps = 24 for hourly ERA5Land
window_steps = 8  for 3-hour target CF
```

4. 单元测试覆盖 `clim_tbl/thr` 外部传入路径。

### 5.4 修改 Pipeline B：`scripts/station_signals_direct.py`

CLI 改为：

```text
--cf_root data/cfs
--lowres_threshold_dir outputs/low_resource_thresholds/sparse_station_ERA5Land_2015-2025
--no_low_resource
```

删除或废弃：

```text
--lowres_baseline_years
```

处理流程：

1. 当前 weather 简单事件保持不变。
2. 默认计算 `low_resource`。
3. 根据 `scenario + tech` 选择稀疏阈值文件：

```text
wind  -> low_resource_threshold_sparse_<scenario>_wind_ERA5Land_2015-2025.nc
solar -> low_resource_threshold_sparse_<scenario>_solar_ERA5Land_2015-2025.nc
```

4. 读取目标模式/SSP 的 CF 到场站。
5. 场站经纬度匹配到同 SSP 稀疏阈值文件的 station 维度。
6. 使用 ERA5Land `clim/thr` 判定低资源。
7. 仍应用：
   - `activation_year` 掩膜；
   - `match.valid` 或 `match_dist_deg` 掩膜；
   - 光伏夜间剔除。

输出 attrs 增加：

```text
low_resource_threshold_file = ...
low_resource_threshold_source = ERA5Land
low_resource_threshold_baseline_years = 2015-2025
low_resource_threshold_match_max_dist_deg = ...
```

Pipeline B 是优先改造对象，因为只处理场站点位，内存风险低于全网格。

## 8. 风险与处理

1. **ERA5Land 全球小时 CF 文件很大**
   - 单月变量约 `(720/744, 1801, 3600)`。
   - 预计算必须按空间块读取，不能全量载入内存。

2. **滚动窗口跨月**
   - 24h 居中滚动需要前后月份边界数据。
   - 按月处理时必须读取相邻月份边界，或先实现按空间块跨完整时间轴流式处理。

3. **ERA5Land 文件未传完或后续重传**
   - 预计算前必须按技术检查 `2015-01` 至 `2025-12` 月文件完整性。
   - 当前风电已完整；光伏若仍缺月，只能生成调试阈值，不能作为正式光伏低资源结果。

4. **ERA5Land 稀疏阈值与目标 SSP CF 网格不同**
   - 阈值文件按场站点匹配；目标 SSP CF 仍按当前最近邻方式抽取。
   - 稀疏阈值文件中找不到同一 `(lon, lat, type)` 时，对该场站置 0，并写入 skipped/invalid reason。

5. **1h 阈值 vs 3h 目标 CF**
   - ERA5Land 阈值的 `clim(month,hour)` 是 24 个小时槽。
   - 3h 目标 CF 只会访问其中 8 个小时槽，这是允许的。
   - 目标 CF 的 24h 滚动窗口仍按自身时间步推断，3h 数据使用 8 步。

6. **旧输出属性语义污染**
   - 旧版本 attrs 里的 `low_resource_baseline_years=2015-2029` 代表目标 CF 内部基线。
   - 新版本必须改为 `low_resource_threshold_baseline_years=2015-2025`，避免混淆。
