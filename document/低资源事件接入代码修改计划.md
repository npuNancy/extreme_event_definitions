## 2. 低资源事件口径

### 2.1 本次默认口径

因为本次明确指定数据为 `data/cfs`，默认实现为：

> 基于容量因子 CF 的低资源事件。

风电使用 `wind_cf(time, ...)`，光伏使用 `solar_cf(time, ...)`。二者单位均为 `1`，范围理论上为 `[0, 1]`。

旧文档中低资源写作“风=10m 风速、光=rsds 辐照”的资源距平。该口径需要原始气象资源序列，不是本次指定的 `data/cfs`。如果后续要恢复旧口径，需要另开一条数据入口。

### 2.2 计算公式

对每个网格点或场站 `k`，容量因子序列记为 `CF(t, k)`。

1. 计算 24h 居中滚动均值：

\[
R(t,k)=\operatorname{mean}\{CF(\tau,k): \tau \in W_{24h}(t)\}
\]

其中 `W_24h(t)` 是以 `t` 为中心的 24 小时窗口；窗口不完整或含有效值不足时记为 `NaN`。

2. 按月×小时构造气候态：

\[
C(m,h,k)=\operatorname{mean}\{R(t,k): month(t)=m,\ hour(t)=h,\ t \in B\}
\]

其中 `B` 是基线期掩膜。
ps：这里 有12个月，8个小时时刻，因为 CF 文件是 3 小时步长。

3. 计算距平：

\[
A(t,k)=R(t,k)-C(month(t),hour(t),k)
\]

4. 每个点/站独立计算 P5 阈值：

\[
T(k)=P_5\{A(t,k): t \in B\}
\]

5. 低资源事件：

\[
signal\_low\_resource(t,k)=A(t,k)\le T(k)
\]

6. 光伏夜间处理：

如果采用 CF 口径，夜间 CF 通常为 0。为避免“所有夜间都被判为低资源”，计划仍沿用现有 `solar_low_resource.signal(...)` 的夜间剔除逻辑：

\[
signal(t,k)=False,\quad solar\_elevation(t,k)\le 0
\]

### 2.3 时间分辨率

CF 文件实测为 3 小时时间步：

- `time.units = days since 2015-01-01`
- 前几个值为 `0.0625, 0.1875, 0.3125...`，即 1.5h、4.5h、7.5h...，步长 3h。

现有 `common.roll24c()` 固定用 24 个时间步，适用于逐小时数据；直接用于 3h CF 会变成 72h 窗口，这是错误的。

计划修改 `common.py`：

- 新增按时间轴自动推断窗口长度的函数：

```text
timestep_hours = median(diff(time)) in hours
window_steps = round(24 / timestep_hours)
```

- 对 3h CF：`window_steps = 8`
- 对 1h CF：`window_steps = 24`

### 2.4 `t` 与 `t+1` 标记

现有低资源算法会把事件标记到 `t` 和 `t+1`：

```python
ev2[1:] |= ev[:-1]
```

在 3h CF 中，`t+1` 表示下一个 3h 时间步。计划保留该行为以兼容既有事件定义，但在输出全局属性中写明：

- `low_resource_mark_next_step = true`
- `low_resource_timestep_hours = 3.0`

如果后续认为 3h 下不应扩展到下一步，可加 CLI 参数关闭；第一版不增加额外分支。

## 4. 代码修改计划

### 4.1 新增 CF 读取与低资源工具

新增模块：

```text
../grid_extreme_signals/cf_low_resource.py
```

职责：

1. 根据 `source / tech / model / region / scenario` 查找 CF 文件。
2. 使用 `h5py` 读取：
   - `time`
   - `lat/lon` 或 `rlat/rlon + lat/lon`
   - `solar_cf` / `wind_cf`
3. 将 NetCDF time units 转为 `pandas.DatetimeIndex`。
4. 支持规则经纬度网格的场站 gather：
   - 输入 `StationMatch`
   - 分块读取 `cf_var[:, lat_idx, lon_idx]`
   - 输出 `(time, n_station)` 的 CF 数组
5. 支持网格级分块计算：
   - 对规则网格按空间块读取 `(time, lat_chunk, lon_chunk)`
   - 计算 `signal_low_resource`
   - 写回输出 Dataset
6. 预留 NAM-12：
   - 如果 CF 文件含二维 `lat/lon` 辅助坐标，则复用 `match_2d`
   - 当前目录无实际 `.nc` 时只做接口与测试，不做实数据验证

### 4.2 修改 `common.py`

目标：让现有低资源算法支持 1h / 3h / 其他规则时间步。

计划改动：

1. 新增：

```python
def infer_timestep_hours(time) -> float
def window_steps_for_24h(time) -> int
def roll_centered_steps(a, window_steps: int) -> np.ndarray
```

2. 修改 `low_resource(...)` 支持：

```python
def low_resource(..., window_steps=None, mark_next_step=True):
```

3. 默认行为：

- `window_steps is None` 时按 `time` 自动推断 24h 对应步数
- 保留 `mark_next_step=True`

4. 保留旧 API，不破坏已有调用。

### 4.3 修改 `events/wind_low_resource.py` 和 `events/solar_low_resource.py`

```python
    return common.low_resource(..., window_steps=window_steps, mark_next_step=mark_next_step)
```

### 4.4 修改 `grid_extreme_signals/signal_runner.py`

目标：网格级 Pipeline 生成 `signal_low_resource`，供 Pipeline A 抽取。

CLI 参数由 `generate_multi_source_grid_signals.py` 提供。低资源默认启用，因此参数设计为：

```text
--cf_root ../data/cfs
--lowres_baseline_years 2015-2029
--no_low_resource
```

运行逻辑：

1. 原有简单事件保持不变。
2. 默认计算 `low_resource`；只有显式传入 `--no_low_resource` 时跳过。
3. 计算时：
   - 根据当前 task 查找 CF 文件
   - 用 CF 计算 `low_resource`
   - 将 `masks["low_resource"]` 合并进输出
4. `supported_events` 包含 `low_resource`
5. 输出 attrs 增加：
   - `low_resource_source = capacity_factor`
   - `low_resource_cf_file = ...`
   - `low_resource_baseline_years = ...`
   - `low_resource_window_hours = 24`
   - `low_resource_timestep_hours = ...`

注意：网格级低资源计算需要按空间块处理，不能一次性把完整 CF 文件载入内存。

### 4.5 修改 `scripts/station_signals_direct.py`（Pipeline B）

目标：直接场站流程输出 `signal_low_resource`。

CLI 参数。低资源默认启用，因此参数设计为：

```text
--cf_root ../data/cfs
--lowres_baseline_years 2015-2029
--no_low_resource
```

处理流程：

1. 现有 weather → `registry.simple_signals(...)` 不变。
2. 默认计算 `low_resource`；只有显式传入 `--no_low_resource` 时跳过。
3. 计算时：
   - 找到对应 CF 文件
   - 复用当前 `match` 将 CF gather 到场站 `(time, n_station)`
   - 用 `registry.LOWRES[tech].signal(...)` 计算低资源
   - 按请求年份裁剪到与当前输出时间一致
   - 写入 `out_masks["signal_low_resource"]`
4. 仍然应用：
   - `activation_year` 掩膜
   - `match.valid` 距离掩膜
5. `supported/skipped` 中纳入 `low_resource`。

Pipeline B 是第一优先级，因为它只对场站取点，内存风险显著低于全网格低资源。

### 4.6 修改 `scripts/station_signals_from_grid.py`（Pipeline A）

目标：Pipeline A 可以得到 `signal_low_resource`。

推荐方案：

1. 当传入 `--run_phase1` 时，默认将低资源参数传给第一阶段 runner；只有显式传入 `--no_low_resource` 时跳过。
2. 抽取阶段不做特殊判断；只要网格文件中有 `signal_low_resource`，它会像其他 `signal_*` 一样被抽取。
3. 如果默认低资源启用，但已有 `--grid_signals_dir` 中缺少 `signal_low_resource`：
   - 明确报错，提示需要重新运行第一阶段并开启 `--include_low_resource`
   - 不在 Pipeline A 抽取阶段静默补算，避免“Pipeline A”语义混乱

### 4.7 修改 `scripts/generate_multi_source_grid_signals.py`

新增 CLI 参数并传入 runner。低资源默认启用：

```text
--cf_root ../data/cfs
--lowres_baseline_years 2015-2029
--no_low_resource
```

默认启用低资源。用户显式加 `--no_low_resource` 后才跳过。

### 4.8 临时补写脚本

新增临时脚本：

```text
./patch_pipelineB_low_resource.py
```

用途：

只运行风电和光伏的 `low_resource` 事件，不重新计算已经完成的简单事件；结果直接写入已有文件：

```text
/data6/yanxiaokai/project_climate/extreme_event_definitions/outputs/station_signals_pipelineB/regional_bcsd/NESM3
```

默认参数：

```text
--output_root ../outputs/station_signals_pipelineB/regional_bcsd/NESM3
--cf_root ../data/cfs
--model NESM3
--baseline_years 2015-2029
--years 2015-2060
--tech both
--scenario all
--region all
```

写入策略：

1. 遍历已有 `station_signals_{wind,solar}_NESM3_<region>_<scenario>_2015-2060.nc`。
2. 根据文件路径找到对应 CF 文件：
   - 光伏：`../data/cfs/CFs_of_solar/NESM3/<region>/solar_CF_<region>_NESM3_<scenario>_2015-2060_allmonths.nc`
   - 风电：`../data/cfs/CFs_of_wind/NESM3/<region>/wind_CF_<region>_NESM3_<scenario>_2015-2060_allmonths.nc`
3. 从已有结果文件读取 `station_lon/station_lat/activation_year/match_dist_deg/time`。
4. 从 CF 文件读取 `lat/lon/time/solar_cf|wind_cf`，逐文件归一经度后将 CF 最近邻抽取到场站。
5. 用 `2015-2029` 作为基线期计算 `signal_low_resource`。
6. 应用已有 `activation_year` 和 `match_dist_deg <= max_match_dist_deg` 掩膜。
7. 若文件已存在 `signal_low_resource`：
   - 默认跳过；
   - 传入 `--overwrite` 时覆盖。
8. 更新全局属性：
   - `supported_events` 加入 `low_resource`
   - `skipped_events` 删除 `low_resource`
   - 增加 `low_resource_source/cf_file/baseline_years/window_hours/timestep_hours`

该脚本是临时补丁工具；正式方案仍按 4.4-4.7 接入两个 pipeline。

## 8. 风险与处理

1. **3h 时间步窗口风险**
   - 不能沿用固定 24 个样本窗口。
   - 必须按时间步推断 `24h / dt`。

2. **CF 文件很大**
   - Germany 单变量形状约 `(134416, 81, 101)`。
   - 中国约 `(134416, 348, 442)`。
   - 网格级低资源必须空间分块；场站级优先实现。

3. **NetCDF4 读取依赖**
   - 当前环境不能用 xarray 打开这些 CF 文件。
   - 第一版使用 `h5py` 读取，避免新增依赖。

4. **经度约定不一致**
   - BCSD CF 与气象一样，Portugal 为 `[0,360)`，Germany 为常规正经度。
   - 必须复用逐文件经度归一。

5. **NAM-12 当前缺少实际文件**
   - 代码接口预留。
   - 单元测试用合成二维网格文件覆盖。
   - 实数据到位后再做冒烟测试。

6. **低资源口径变更**
   - 本计划默认 `capacity_factor` 口径。
   - 输出 attrs 必须写明，避免与旧的 `wind_ms/rsds` 口径混淆。
