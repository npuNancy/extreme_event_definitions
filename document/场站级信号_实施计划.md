# 场站级极端天气信号 —— 两阶段合并实施计划（Pipeline A / Pipeline B）

> 状态：草案，待确认后实施。
> 范围：在已有的「多数据源网格信号流程（第一阶段）」之上，新增**场站级**极端天气信号能力，
> 提供两条独立 pipeline（两个脚本），并对全场站中**仅有气象数据的那些国家**做处理。

---

## 0. 背景与目标

### 0.1 现状更新（与旧文档的关键差异）
- 旧 spec（`修改输入输出说明_多数据源网格版.md` §2.3）把场站当作 **1°×1°**、并据此把"场站筛选"整体推迟到第二阶段。
- **实际情况已变**：场站选址结果已是 **0.1°（≈10km）级别**，落在 `data/stations/*.csv`。
- 因此"场站 ↔ 网格"不再是"降尺度聚合"，而是**同尺度配准取点（最近邻）**——可立即实施。

### 0.2 目标
1. 只对**有气象数据覆盖的国家**范围内的场站计算极端天气信号（全场站是全球的，气象只有少数国家）。
2. 提供两条 pipeline，**分别写成独立 Python 脚本**，避免耦合：
   - **Pipeline A（先网格后场站）**：先跑第一阶段（全场站所在区域的网格信号），再从网格信号抽取到场站。
   - **Pipeline B（直接场站）**：跳过网格，直接对场站点加载气象→标准化→检测→写出。

### 0.3 交付物 = 场站级「极端天气信号」
本计划交付的是**每个场站的极端天气事件掩码**（布尔/`int8`，复用 `registry.simple_signals` 的全部简单阈值事件）。
> 注：参考仓库 `calculate_wind_solar_out` 算的是"出力（power = CF×容量）"；本计划**只参考它的场站配准/经度/国界匹配逻辑**，不复用其出力公式。若你确实需要"场站出力"而非"场站信号"，请在【开放问题 Q1】确认。

### 1.1 场站选址数据 `data/stations/*.csv`

- 实测：Germany bbox（lon 5–15, lat 47–55）内 SSP1-2.6 有 3866 个场站，足够做冒烟测试。

### 1.3 国界 shapefile（场站→国家归属必需）
- 路径：`/data6/yanxiaokai/project_climate/data/maps/natural_earth/ne_110m_admin_0_countries.shp`（项目 `data/` 下暂无，指向上一级；可软链到本项目 `data/maps/` 或用绝对路径）。
- 参考代码已验证：`pyshp`(`shapefile`) 读 + `shapely` `prepared.contains(Point(lon,lat))` 做 point-in-polygon；BCSD 目录名→Natural Earth `NAME` 映射表 `BCSD_REGION_TO_NAME`（如 `South-Africa→"South Africa"`、`México→"Mexico"`、`United-Kingdom→"United Kingdom"`）。

### 1.4 事件检测 API（决定了 Pipeline B 可干净复用）
- `registry.simple_signals(tech, weather_dict, skip_missing=True)` → `{event_name: (T,K) bool}`，**K 是末尾"空间/对象"轴，天然向量化**。
- 每个 `events/<name>.signal(w)` 是**纯 numpy**（输入仅 weather 字典），因此 `K=场站数` 时直接可用：把每个统一气象变量 gather 成 `(T, n_stations)` 即可。
- **低资源事件 `signal_low_resource` 暂缓**（签名不同、需 clim288 基线、且 3h/1h 分辨率不可比）——与第一阶段一致，本计划不实现。

## 2. 经度约定（本任务第一风险点，已实测）

### 2.1 各数据经度范围（实测/已确认）
| 数据 | 经度约定 | 依据 |
|---|---|---|
| 场站 CSV | **[-180,180)** | `lon∈[-175.2,178.3]` |
| BCSD 气象 | **区域间不一致！** | Germany `lon 5–15`（像 [-180,180]），Portugal `lon 328.7–353.7`（即 [-31,-6]，**[0,360)**）。 |
| China(CMFD) | 预计 [0,360) | 待数据落盘复核 |
| NAM-12 | [-180,180] | 旋转极，2D `lon` 辅助坐标 |

> ⚠️ **关键结论**：BCSD 的经度约定**逐区域不同**（西半球/负经度国家被存成 [0,360)，东半球/正经度国家保持 [-180,180]）。**任何"BCSD 统一为某约定"的假设都是错的。**

### 2.2 处理原则（必须遵守）
- **匹配前一律把网格经度与场站经度都归一到同一个规范区间 `[-180,180)`**，逐文件检测：
  - 若该网格 `lon.max() > 180` → 判定为 [0,360)，用 `((lon+180)%360)-180` 转回 [-180,180)；
  - 否则原样使用。
- 场站 `lon` 本就是 [-180,180)，国界 `contains` 也用 [-180,180)。
- 最近邻经度距离用**环形距离** `abs(((a-b+180)%360)-180)`，正确处理 ±180° 缝合（如西班牙/爱尔兰/阿拉斯加）。
- 已验证工具函数（移植自 `ref_code/.../station_output_calculator_0p1deg.py`）：`lon_to_360`(:100)、`lon_to_180`(:105)。

## 4. Pipeline A —— 网格信号 → 场站抽取

**脚本**：`scripts/station_signals_from_grid.py`

**流程**：
1. （可选）跑第一阶段：对 `--source/--model/--scenario`（+ `--region all` 或指定区域）调用现有 `run_signal_pipeline`，产出网格级 `extreme_signals_<tech>_<region>_<model>_<scenario>_<year>.nc`。
   - 提供 `--grid_signals_dir <已有目录>`：若第一阶段已跑过，**跳过重跑**，直接读取已有网格信号。
2. 对每个区域、每个 tech、每年份的网格信号文件：
   - 读出该区域的网格 `lat/lon`（检测并归一经度）；
   - 用 `station_match` 取该国家多边形内的场站 + 最近邻格点索引 + 距离；
   - 把**布尔掩码变量**按 `(lat_idx, lon_idx)` 从 `(time,lat,lon)` gather 到 `(time, station)`；
   - `activation_year` 掩码（`time.year < activation_year` → 0）、`dist>MAX_DIST` → 0；
   - 写场站级信号文件（见 §6）。

**复用**：第一阶段 runner（不改）+ `station_match`。**优点**：完全复用第一阶段，网格信号也可另作他用。**缺点（你已指出）**：会计算区域内**所有格点**，效率低。

## 5. Pipeline B —— 直接场站出力（只算场站）

**脚本**：`scripts/station_signals_direct.py`

**流程**（按 `--source`，对每个有数据的区域 × 情景）：
1. 复用现有 adapter 的 `iter_tasks` / `load_wind_weather` / `load_solar_weather`，得到该区域**已标准化的气象**（`temp_C/wind_ms/precip_mmh/rsds/rh_pct` 等，在区域原网格上）。
2. 读区域网格 `lat/lon`（归一经度）；用 `station_match` 筛出该国场站 + 最近邻索引 + 距离。
3. **把每个标准化气象变量 gather 到场站**：`var[:, lat_idx, lon_idx] → (T, n_stations)`；组成 `weather_dict`。
4. `registry.simple_signals(tech, weather_dict, skip_missing=True)` → `(T, n_stations)` 掩码。
5. `activation_year` 掩码 + `dist>MAX_DIST` → 0；记录 `supported/skipped_events`。
6. 写场站级信号文件（见 §6）。**全程不写网格信号文件。**

**时间/内存**：按年（BCSD 的 task 粒度）+ 年内按 `chunk_time` 分块；每块读该区域完整空间切片（Germany 81×101 很小；大区域可加 bbox 子窗口降 IO，参考 ref `:631-655`），gather 成 `(chunk, n_stations)`。

**复用**：现有 adapter（气象加载+标准化，**不改 adapter**）+ `station_match` + `registry`。
**优点**：只检测场站、跳过全场网格检测；若场站集合变化才需重跑。**缺点**：不产出网格信号。

> 两条 pipeline 都把"气象标准化"和"事件检测"交给现有代码，**新逻辑只有：场站匹配 + gather + 场站级写出**，因此增量小、风险可控。

## 6. 输出格式（场站级 NetCDF）

- 维度：`time`、`station`
- 事件变量（每个支持的简单阈值事件一个，`int8` 0/1）：`signal_<event>(time, station)`，如 `signal_high_temp`、`signal_rainstorm`…
- 场站元数据变量（`station` 维）：`station_lon`、`station_lat`、`station_type`(0=光伏/1=风电)、`capacity_gw`、`activation_year`、`match_dist_deg`、`source_region`
- 全局属性：`source`、`model`、`scenario`、`source_csv`、`grid_resolution="0.1deg"`、`match_method="nearest"`、`max_match_dist_deg`、`supported_events`、`skipped_events`、`pipeline="A|B"`、`n_stations`
- 输出粒度（默认，可在【开放问题 Q3】改）：**一个文件 per `(source, scenario, tech)`**，聚合该 source 下所有匹配到场站（用 `source_region` 区分国别）；默认根目录 `outputs/station_signals/`。
- `activation_year` 掩码默认开启（场站激活年前信号置 0），可用 `--no-activation-mask` 关闭。

## 10. 风险与注意事项

1. **经度约定区域间不一致（最高风险）**：必须逐文件 `detect_lon_convention` 后再归一；任何硬编码假设都会错配西半球国家。
2. **海洋格点**：BCSD 区域文件含国界 bbox 内的海洋格点；气象在海洋上仍有值（不像 CF 那样需要 land mask），且 0.1° 最近邻≈精确，国界多边形已保证场站在陆上，风险低；如需更严可后续引入 land mask。
3. **内存/IO**：BCSD 单文件 2–3GB；按年 task + 年内 `chunk_time` 分块；大区域可加场站 bbox 子窗口降 IO。
4. **`MAX_DIST`**：默认 0.15°（BCSD≈0；China/NAM-12≈0.05–0.11，在容差内）。超容差不丢弃场站，而把其信号置 NaN/0 并在汇总里计数。
5. **跨经度数据源冲突**：同一场站理论上可能落入多个数据源；沿用参考做法——`--source` 一次只跑一类，互不干扰。
6. **低资源事件**：本计划不实现（与第一阶段一致），输出 `skipped_events` 会含 `low_resource`。
