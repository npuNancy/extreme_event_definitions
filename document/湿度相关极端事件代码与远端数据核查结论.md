# 湿度相关极端事件代码与远端数据核查结论

## 实施状态

本文第 2—6 节记录的是修改前代码和远端既有产物的核查事实。截至
2026-07-23，本地工作区已经按第 7 节完成代码接入：

- `RegionalBcsdAdapter` 已读取 `hurs_bcsd` 并生成 `rh_pct`；
- 缺失单位的 regional BCSD `hurs` 按已核实的百分比产品契约处理，同时执行
  物理范围校验；
- 风电湿度对齐到 `uas/vas` 时间轴；
- 光伏湿度插值到 `rsds` 时间轴；
- 若历史 BCSD 变量与后来按新 BBOX 裁剪的 `hurs` 网格不一致，则仅对 `hurs`
  启用空间特判：所有参与计算的变量统一裁到参考网格与 `hurs` 的共同经纬度
  坐标；非 `hurs` 变量之间仍执行严格网格一致性校验；
- 四类湿度事件已纳入自动化测试。

远端 `scnet-wuzhen-199` 的旧提交和既有 125 个输出尚未因本地代码修改而自动改变。
只有完成代码部署并重新运行 `step2E1 → step2E2` 后，远端正式产物才会包含这些
湿度事件。

## 1. 核查背景

本次核查针对以下四个湿度相关极端事件：

| 技术类型 | 事件 | 判定条件 |
|---|---|---|
| 风电 | `hot_humid` | `temp_C > 30` 且 `rh_pct >= 85` |
| 风电 | `icing` | `temp_C < -2` 且 `rh_pct >= 85` |
| 光伏 | `high_humidity` | `rh_pct >= 95` |
| 光伏 | `icing` | `temp_C < -2` 且 `rh_pct >= 85` |

相关生产流程在远程服务器 `scnet-wuzhen-199` 上按以下顺序执行：

```text
step1 → step2E1 → step2E2
```

问题来源文档为：

```text
/data6/yanxiaokai/project_climate/calculate_wind_solar_generation_loss/
  document/风光出力损失输入与信号对齐问题说明.md
```

其中“问题 2”原先认为 regional BCSD 输入没有湿度数据。本次结合当前代码、
远端实际输入文件和已生成输出进行复核后，确认该描述已经不符合远端数据现状。

## 2. 最终结论

当前生产代码确实不会计算上述四个湿度相关事件。

但是，直接原因不是远端缺少湿度文件，而是
`RegionalBcsdAdapter` 没有读取已经存在的 `hurs` 文件，并且仍然无条件记录：

```text
rh_pct: BCSD 无湿度数据
```

因此：

1. 四个事件定义及注册关系已经存在；
2. step2E1 加载的 `weather` 中没有 `rh_pct`；
3. 普通事件计算使用 `skip_missing=True`；
4. 依赖 `rh_pct` 的事件因 `KeyError` 被跳过；
5. step2E2 只计算或补写 `signal_low_resource`，不会补算湿度事件；
6. 现有生产输出缺少这四类信号是当前代码行为的必然结果。

## 4. `xxx_bcsd` 变量名是否已经转换

是。当前其他 BCSD 变量的 NetCDF 内部变量名同样通常为 `xxx_bcsd`，代码已经有
统一的变量名解析机制。

### 4.1 原始文件名和内部变量名

典型输入如下：

| 逻辑变量 | 文件名前缀 | NetCDF 内部变量名 |
|---|---|---|
| 温度 | `tas_3h_bcsd_...nc` | `tas_bcsd` |
| 东西向风 | `uas_3h_bcsd_...nc` | `uas_bcsd` |
| 南北向风 | `vas_3h_bcsd_...nc` | `vas_bcsd` |
| 降水 | `pr_3h_bcsd_...nc` | `pr_bcsd` |
| 短波辐射 | `rsds_3h_bcsd_...nc` | `rsds_bcsd` |
| 相对湿度 | `hurs_3h_bcsd_...nc` | `hurs_bcsd` |

### 4.2 现有解析机制

`grid_extreme_signals/io_utils.py` 中的 `get_var_name()` 按以下优先级解析：

1. `{preferred}_bcsd`；
2. `{preferred}`；
3. 当数据集中只有一个数据变量时，使用该唯一变量。

例如：

```python
get_var_name(ds, "tas")
```

会优先返回：

```text
tas_bcsd
```

`prepare_dataarray()` 随后使用解析出的真实变量名读取数据，并把维度顺序整理为：

```text
time, lat, lon
```

因此，代码不要求输入文件内部变量必须直接叫 `tas`、`pr` 或 `rsds`。

### 4.3 从输入变量到内部统一气象变量

变量名解析完成后，适配器还会进行单位和语义标准化：

| BCSD 输入 | 内部统一变量 | 处理 |
|---|---|---|
| `tas_bcsd` | `temp_C` | 从 K 或其他受支持单位转换为摄氏度 |
| `uas_bcsd`、`vas_bcsd` | `wind_ms` | 计算 `sqrt(uas² + vas²)` |
| `pr_bcsd` | `precip_mmh` | 转换为 `mm h-1` |
| `rsds_bcsd` | `rsds` | 转换为 `W m-2` |

所以“`hurs_bcsd` 标准化为 `rh_pct`”并不是引入一种新的特殊命名方式，而是让
湿度沿用当前适配器已有的两层处理：

```text
hurs_bcsd
  └─ get_var_name/prepare_dataarray 解析真实输入变量
       └─ 湿度单位校验和转换
            └─ 内部统一变量 rh_pct
```

需要注意，`hurs_bcsd → rh_pct` 不应只做变量重命名。还必须确认输入采用：

```text
0—100 %
```

还是：

```text
0—1
```

并统一输出为百分比。远端抽样文件的 `hurs_bcsd` 没有 `units` 属性，因此需要为
regional BCSD 湿度制定明确的缺失单位处理规则和数值范围校验。

## 7. 建议修改范围

### 7.1 适配器

在 `RegionalBcsdAdapter` 中：

1. 使用现有 `_open_and_prepare(task, "hurs", ...)` 读取 `hurs_bcsd`；
2. 增加相对湿度单位标准化函数，将结果统一为 `rh_pct`；
3. 对百分比范围进行校验，合理处理轻微越界值；
4. 风电将 `rh_pct` 对齐到 `uas/vas` 时间轴；
5. 光伏将 `rh_pct` 插值到 `rsds` 时间轴；
6. 将 `rh_pct` 加入返回的 `WeatherBundle.dataset`；
7. 只有 `hurs` 确实缺失或无效时，才记录湿度输入跳过原因；
8. 将 `hurs` 加入空间网格一致性校验。

### 7.2 单元测试

至少应覆盖：

1. `get_var_name(ds, "hurs")` 正确解析 `hurs_bcsd`；
2. `hurs` 百分比输入正确生成 `rh_pct`；
3. 如允许 0—1 输入，正确转换为 0—100；
4. 缺失 `units` 时按 regional BCSD 的明确规则处理；
5. 非法范围或无法识别单位时失败，而不是静默产生错误结果；
6. 风电生成 `hot_humid` 和 `icing`；
7. 光伏生成 `high_humidity` 和 `icing`；
8. 光伏 `hurs → rsds` 时间插值正确；
9. 缺少 `hurs` 时保持当前可选事件跳过行为；
10. `--require_events` 要求湿度事件时，缺少输入应报错。

### 7.3 生产重跑

修复并部署后：

```text
不重跑 step1
重新运行 step2E1
重新运行 step2E2
```

必须先用带覆盖语义的新 step2E1 结果替换旧文件，再运行 step2E2 补回
`signal_low_resource`。不能只运行 step2E2，因为它不会计算普通湿度事件。

重跑后的验收条件至少包括：

- 风电输出存在 `signal_hot_humid` 和 `signal_icing`；
- 光伏输出存在 `signal_high_humidity` 和 `signal_icing`；
- `supported_events` 包含对应事件；
- `skipped_events` 不再把这些事件标记为缺少湿度；
- 原有非湿度事件仍然存在；
- step2E2 完成后 `signal_low_resource` 仍然存在；
- 信号维度、时间轴、场站顺序和投产年份掩膜口径符合下游要求。
