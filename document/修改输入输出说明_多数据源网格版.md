# 修改输入输出说明：多数据源网格极端天气信号生成

> 本文用于指导 Claude Code 修改当前仓库的 `dev-BCSD-Mutli-Region` 分支。
>
> 目标是在不破坏现有 ERA5-Land 真实场站流程的前提下，新增一套 **多数据源规则网格 / 旋转极网格 → 极端天气信号** 的处理流程。
>
> 本说明进一步参考 `ref_code/calculate_bcsd_cfs` 中已有的容量因子计算脚本。容量因子代码已经分别处理：
>
> 1. 多数区域或国家的 **CMIP6–ERA5Land BCSD** 数据；
> 2. 中国区域的 **CMIP6–CMFD BCSD** 数据；
> 3. 美国 / 北美区域的 **CMIP6–CORDEX NAM-12** 数据；
> 4. 原始 **ERA5-Land** 全球逐小时数据。
>
> 极端天气信号代码应复用这些代码中已经验证过的文件发现规则、网格结构、时间轴处理方式和单位转换思路，但不要直接复制容量因子计算公式。
>
> 本版新增两项强制要求：
>
> 1. 旧的真实场站脚本迁移到 `legacy_station_pipeline/`，不再放在项目根目录；
> 2. `weather_*.nc` 是可选中间产物，默认只在内存或分块中计算天气变量并直接生成信号，不保存天气文件。

## 0.2 旧的真实场站脚本必须迁出项目根目录

旧脚本继续保留，但**不得继续散落在项目根目录**。统一迁移到：

```text
legacy_station_pipeline/
```

迁移映射：

| 原位置 | 新位置 |
|---|---|
| `global_extreme_simple_signals.py` | `legacy_station_pipeline/global_extreme_simple_signals.py` |
| `extract_station_weather_nc.py` | `legacy_station_pipeline/extract_station_weather_nc.py` |

| `weather_loaders.py` | `legacy_station_pipeline/weather_loaders.py` |

这些脚本继续服务于：

```text
ERA5-Land / MERRA-2 + 真实场站 CSV 或 GPKG
        ↓
(time, station)
        ↓
逐站极端天气信号
```

新增多数据源流程服务于：

```text
区域或全球网格气象数据
        ↓
保持原始空间网格
        ↓
(time, spatial_dims...)
        ↓
逐网格极端天气信号
```

迁移时必须同步修复旧脚本内部 import。推荐使用包内导入，例如：

```python
from legacy_station_pipeline.weather_loaders import ...
```

旧脚本的推荐运行方式改为：

```bash
python -m legacy_station_pipeline.generate_extreme_signals ...
```

根目录中不要保留同名兼容脚本或薄包装器，避免 Claude Code 后续误改两套文件。共享的 `events/`、`registry.py` 与 `common.py` 可以继续保留在根目录。不要把新的多数据源逻辑硬塞入旧脚本。

## 0.3 第一阶段默认使用全部网格点

场站选址结果是可选项。

新增命令行参数：

```text
--stations_dir
```

默认值：

```python
None
```

行为：

| `--stations_dir` | 第一阶段行为 |
|---|---|
| 未传入或为 `None` | 对数据源中的全部网格点计算极端天气信号 |
| 非空目录 | 明确抛出 `NotImplementedError` |

第一阶段必须包含：

```python
if args.stations_dir is not None:
    raise NotImplementedError(
        "Station-filter mode is reserved but not implemented yet. "
        "Omit --stations_dir to run all-grid mode."
    )
```

不能静默忽略该参数，也不能让用户误以为已经执行了场站筛选。

## 0.4 `weather_*` 中间文件默认不保存

极端天气信号计算仍然需要在内存或分块流式处理中构造标准化天气变量，例如：

```text
temp_C
wind_ms
precip_mmh
rsds
rh_pct
dust_aod
```

但是，默认流程只生成最终的：

```text
extreme_signals_*.nc
```

不要默认把标准化天气变量额外落盘为：

```text
weather_*.nc
```

新增参数：

```text
--save_weather
```

默认值：

```python
False
```

行为：

| `--save_weather` | 行为 |
|---|---|
| 未传入 | 仅在内存或时间分块中计算标准化天气变量，并直接生成信号；不创建 `weather/` 目录，不写出 `weather_*.nc` |
| 已传入 | 在生成信号的同时，可选写出 `weather_*.nc`，用于调试、检查单位转换或复用中间结果 |

这里的“默认不保存天气文件”不等于“不计算天气变量”。事件判定仍然依赖标准化天气变量，只是不将其物化为 NetCDF 中间产物。

建议入口中使用：

```python
if args.save_weather:
    write_weather_dataset(bundle, weather_out_path)
```

信号文件始终写出：

```python
write_signal_dataset(bundle, masks, signal_out_path)
```

# 1. 参考仓库中的四类输入数据

## 1.1 数据源总览

| `--source` | 数据名称 | 典型空间网格 | 时间分辨率 | 第一阶段输出粒度 |
|---|---|---|---|---|
| `regional_bcsd` | 多数区域 / 国家 CMIP6–ERA5Land BCSD | 规则经纬度网格，约 0.1° | 3 小时 | 按年 |
| `china_cmfd_bcsd` | 中国区域 CMIP6–CMFD BCSD | 规则经纬度网格，约 0.1° | 3 小时 | 按年 |
| `cordex_nam12` | CMIP6–CORDEX NAM-12 | 旋转极网格 `rlat × rlon`，带二维 `lat/lon` | 逐小时 | 按年 |
| `era5land_raw` | 原始 ERA5-Land 全球数据 | 规则经纬度网格，约 0.1° | 逐小时 | 按月 |

注意：

1. 四种数据源不能强行共用同一种文件发现规则；
2. CORDEX NAM-12 不能强行改造成一维 `lat × lon`；
3. 原始 ERA5-Land 的 `tp` 与 `ssrd` 是累积量，需要单独做反累积；
4. BCSD 数据通常已经是瞬时量、时段平均值或通量，不能直接套用 ERA5-Land 的反累积逻辑；
5. 网格信号输出必须保留来源数据的空间坐标，便于后续和容量因子结果逐格对齐。

# 2. 可选输入 A：场站选址结果

## 2.1 参数

统一入口预留：

```text
--stations_dir
```

目录中预计包含：

| 文件 | 情景 | 数据文件中的情景代码 |
|---|---|---|
| `stations_SSP1-2.6.csv` | SSP1-2.6 | `ssp126` |
| `stations_SSP2-4.5.csv` | SSP2-4.5 | `ssp245` |
| `stations_SSP5-6.0.csv` | SSP5-6.0 | `ssp585` |

注意：第三个 CSV 文件名为 `SSP5-6.0`，但是对应的气候情景代码仍为 `ssp585`。

## 2.2 CSV 格式

```csv
year,type,lon,lat,capacity_gw
2050,solar,-126.5,54.5,5.7757
2050,solar,-126.5,53.5,3.4574
2050,wind,25.5,62.5,0.1901
2040,solar,12.5,42.5,3.2100
2030,wind,-120.5,51.5,0.8502
```

| 列名 | 类型 | 含义 |
|---|---|---|
| `year` | int | 目标年份：2030、2040、2050 |
| `type` | string | `solar` 或 `wind` |
| `lon` | float | 1°×1° 场站格网中心经度 |
| `lat` | float | 1°×1° 场站格网中心纬度 |
| `capacity_gw` | float | 对应格网的装机容量，单位 GW |

同一个 `(type, lon, lat)` 可能出现在多个目标年份，应先去重，再处理年份激活关系。

## 2.3 为什么第一阶段不实现场站筛选

场站选址结果使用 1°×1° 格网，而四类输入数据的空间结构并不一致：

| 数据源 | 空间结构 | 后续需要明确的映射方式 |
|---|---|---|
| `regional_bcsd` | 规则 0.1° 经纬度网格 | 一个 1° 场站映射到最近 0.1° 格点，还是聚合 1° 范围内多个格点 |
| `china_cmfd_bcsd` | 规则 0.1° 经纬度网格 | 同上 |
| `cordex_nam12` | 旋转极网格，二维 `lat/lon` | 必须基于二维真实经纬度做最近邻或区域覆盖 |
| `era5land_raw` | 全球规则 0.1° 经纬度网格 | 最近邻、区域平均或保留 1° 内全部格点 |

第一阶段不要擅自选择映射规则。

# 3. 数据源 B1：多数区域 / 国家 CMIP6–ERA5Land BCSD

## 3.1 对应容量因子脚本

参考：

```text
calculate_bcsd_CFs/S01E01_Simulate_Solar_CF_BCSD.py
calculate_bcsd_CFs/S01E02_Simulate_Wind_CF_BCSD.py
```

## 3.2 输入目录

```text
{data_dir}/{model}/{region}/{model}/*.nc
```

默认根目录建议：

```text
data/bcsd_outputs
```

示例：

```text
data/bcsd_outputs/MIROC-ES2H/Austria/MIROC-ES2H/
├── pr_3h_bcsd_on_0p1deg_Austria_MIROC-ES2H_ssp126_2015-2060.nc
├── rsds_3h_bcsd_on_0p1deg_Austria_MIROC-ES2H_ssp126_2015-2060.nc
├── tas_3h_bcsd_on_0p1deg_Austria_MIROC-ES2H_ssp126_2015-2060.nc
├── uas_3h_bcsd_on_0p1deg_Austria_MIROC-ES2H_ssp126_2015-2060.nc
└── vas_3h_bcsd_on_0p1deg_Austria_MIROC-ES2H_ssp126_2015-2060.nc
```

## 3.3 文件发现规则

不要硬编码年份范围。

```text
{data_dir}/{model}/{region}/{model}/{var}_3h_bcsd_on_0p1deg_{region}_{model}_{scenario}_*.nc
```

兼容回退模式：

```text
{var}_*_{region}_{model}_{scenario}_*.nc
{var}_*{scenario}*.nc
```

变量：

```text
var ∈ {pr, rsds, tas, uas, vas}
```

## 3.4 NetCDF 内部变量名

优先级：

1. `{var}_bcsd`
2. `{var}`
3. 文件中唯一的 data variable

例如：

```text
pr_bcsd
rsds_bcsd
tas_bcsd
uas_bcsd
vas_bcsd
```

如果无法唯一判断，直接报错。

## 3.5 空间结构

通常为：

```text
(time, lat, lon)
```

坐标别名兼容：

| 逻辑坐标 | 候选名称 |
|---|---|
| 时间 | `time`, `valid_time` |
| 纬度 | `lat`, `latitude` |
| 经度 | `lon`, `longitude` |

输出时保留来源坐标值和排序，不要为了“统一”而无条件改成 `[-180, 180)` 或重新排序。

原因：后续极端天气信号需要和容量因子文件逐格对齐。坐标转换可以作为未来场站匹配时的辅助步骤，但不能改变第一阶段输出网格。

## 3.6 时间轴

文件通常为 3 小时分辨率。

容量因子代码已经体现出两类时间轴：

- `rsds`：时段平均量，通常使用半点时间轴；
- `tas`、`uas`、`vas`：瞬时量；
- 光伏容量因子以 `rsds` 时间轴为主，将 `tas/uas/vas` 线性插值到 `rsds` 时间；
- 风电容量因子以 `uas/vas` 的原始时间轴为主。

极端天气信号流程也应区分风电和光伏的**内部标准化天气数据**。仅在传入 `--save_weather` 时，才分别写出：

```text
weather_wind_*.nc
weather_solar_*.nc
```

建议：

### 风电内部天气数据（启用 `--save_weather` 时写出天气文件）

以 `uas/vas` 公共时间轴为准：

```text
wind_ms = sqrt(uas^2 + vas^2)
```

若 `tas` 与 `uas/vas` 时间轴不同：

- 仅为计算 `signal_high_temp`，将 `tas` 插值到风电时间轴；
- 记录插值方式；
- 不修改原始输入文件。

### 光伏内部天气数据（启用 `--save_weather` 时写出天气文件）

以 `rsds` 时间轴为准：

- 将 `tas`、`uas`、`vas` 插值到 `rsds` 时间轴；
- 若 `pr` 时间轴和 `rsds` 一致，直接使用；
- 若不一致，不要静默按交集裁剪。必须显式报错，或在配置中指定允许的对齐策略。

## 3.7 第一阶段可生成信号

| 技术 | 信号 | 是否输出 |
|---|---|---:|
| wind | `signal_high_temp` | 是 |
| wind | `signal_high_wind` | 是 |
| wind | `signal_icing` | 否，缺少湿度 |
| wind | `signal_hot_humid` | 否，缺少湿度 |
| solar | `signal_freezing_rain` | 是 |
| solar | `signal_rainstorm` | 是 |
| solar | `signal_cold_highwind` | 是 |
| solar | `signal_icing` | 否，缺少湿度 |
| solar | `signal_high_humidity` | 否，缺少湿度 |
| solar | `signal_dust` | 否，缺少沙尘 AOD |
| wind / solar | `signal_low_resource` | 第一阶段暂缓 |

## 4.3 和多数区域 BCSD 的关键区别

中国区域代码直接读取：

```text
rsds
tas
sfcWind
```

其中：

```text
sfcWind
```

已经是 10 m 合成风速，不需要再从 `uas/vas` 计算。

统一天气变量：

```python
temp_C = tas_to_celsius(tas)
wind_ms = sfcWind
rsds = rsds_to_wm2(rsds)
```

## 4.4 降水变量处理

容量因子代码不使用 `pr`，因此不能仅根据容量因子脚本断言中国 BCSD 一定存在降水文件。

适配器应将 `pr` 设计为可选变量：

```text
pr_3h_bcsd_on_0.1deg_china_{scenario}_*.nc
```

行为：

| `pr` 是否存在 | 行为 |
|---|---|
| 存在 | 读取、转换为 `precip_mmh`，输出降水相关事件 |
| 不存在 | 跳过降水相关事件，并在日志与 NetCDF 属性中记录原因 |
| 用户显式要求降水事件 | 若缺失则报错 |

建议新增：

```text
--require_events
```

例如：

```bash
--require_events freezing_rain rainstorm
```

如果所需输入不存在，立即报错。

## 4.5 时间轴

中国区域数据为 3 小时分辨率。


### 风电内部天气数据（启用 `--save_weather` 时写出天气文件）

以 `sfcWind` 原始时间轴为准：

```text

```

### 光伏内部天气数据（启用 `--save_weather` 时写出天气文件）

以 `rsds` 时间轴为准：

```text
weather_solar_china_*.nc
```

若 `pr` 存在，优先要求其时间轴与 `rsds` 一致。若不一致，不要静默裁剪。

# 5. 数据源 B3：CMIP6–CORDEX NAM-12

## 5.1 对应容量因子脚本

参考：

```text
calculate_bcsd_CFs/S04E01_Simulate_Solar_CF_NAM-12.py
calculate_bcsd_CFs/S04E02_Simulate_Wind_CF_NAM-12.py
```

## 5.2 输入目录

```text
{data_dir}/{gcm_model}/{realization}/{rcm_model}/{scenario}/{var}/
```

默认根目录建议：

```text
data/CORDEX-CMIP6/NAM-12/1hr
```

示例：

```text
data/CORDEX-CMIP6/NAM-12/1hr/
└── MPI-ESM1-2-LR/
    └── r1i1p1f1/
        └── CRCM5/
            └── ssp126/
                ├── rsds/
                ├── tas/
                ├── uas/
                └── vas/
```

每个变量目录下通常按年存放文件。

典型匹配规则：

```text
{var}_NAM-12_{gcm_model}_*.nc
```

## 5.3 空间结构：必须保留旋转极网格

NAM-12 的主维度通常为：

```text
(time, rlat, rlon)
```

同时包含二维辅助经纬度：

```text
lat(rlat, rlon)
lon(rlat, rlon)
```

输出必须保留：

```text
time
rlat
rlon
lat(rlat, rlon)
lon(rlat, rlon)
```

禁止：

- 强行改成 `(time, lat, lon)`；
- 把二维 `lat/lon` 当作一维坐标；
- 为了统一格式进行空间重采样；
- 丢弃旋转极坐标元数据。

## 5.4 时间轴

NAM-12 为逐小时数据。

容量因子代码已经明确：

- `rsds` 是时段平均量，时间标签通常在 `:30`；
- `tas`、`uas`、`vas` 是瞬时量，时间标签通常在 `:00`；
- 光伏容量因子保留 `rsds` 的 `:30` 时间轴，将 `tas/uas/vas` 插值到 `rsds` 时间；
- 风电容量因子使用 `uas/vas` 的 `:00` 时间轴。

极端信号流程应保持同样原则。

### 风电内部天气数据（启用 `--save_weather` 时写出天气文件）

```text
weather_wind_NAM-12_*.nc
```

以 `uas/vas` 的整点时间轴为准。

### 光伏内部天气数据（启用 `--save_weather` 时写出天气文件）

```text
weather_solar_NAM-12_*.nc
```

以 `rsds` 的半点时间轴为准，将瞬时变量插值到半点。

## 5.5 降水变量处理

容量因子脚本不使用 `pr`。极端信号适配器应尝试发现：

```text
{data_dir}/{gcm_model}/{realization}/{rcm_model}/{scenario}/pr/
```

行为：

| `pr` 是否存在 | 行为 |
|---|---|
| 存在 | 转换为 `precip_mmh`；若时间轴与 `rsds` 一致则可输出降水事件 |
| 不存在 | 跳过 `freezing_rain`、`rainstorm` |
| 时间轴和 `rsds` 不一致 | 报错或要求显式配置，不要静默按交集裁剪 |

## 5.6 第一阶段可生成信号

| 技术 | 信号 | 是否输出 |
|---|---|---:|
| wind | `signal_high_temp` | 是 |
| wind | `signal_high_wind` | 是 |
| solar | `signal_cold_highwind` | 是 |
| solar | `signal_freezing_rain` | `pr` 存在且可对齐时输出 |
| solar | `signal_rainstorm` | `pr` 存在且可对齐时输出 |
| 湿度相关事件 | — | 否 |
| 沙尘事件 | — | 否 |
| 低资源事件 | — | 第一阶段暂缓 |

## 6.4 ERA5-Land 累积量必须单独处理

ERA5-Land：

```text
tp
ssrd
```

是日内累积量。

不能把 BCSD 的单位转换函数直接用于 ERA5-Land，也不能只做简单的“当前值减上一值”而忽略月初边界。

参考容量因子脚本的处理原则：

- 若时间为 `01:00`，该小时增量等于当前累计值；
- 其他小时增量等于当前累计值减去上一时刻累计值；
- 月初 `00:00` 需要读取前一个月最后一个时刻作为差分起点；
- 如果前一个月文件不存在，应记录警告，并按明确策略处理无法差分的第一个小时；
- 负值裁剪为 0；
- `tp` 从 m 转换为 mm；
- `ssrd` 从 J m⁻² 转换为 W m⁻²。

建议函数：

```python
def deaccumulate_era5land_month(
    current_accum,
    current_time,
    previous_month_last_value,
    *,
    variable,
):
    ...
```

禁止在 BCSD 适配器中调用此函数。


# 7. 统一天气变量

## 7.1 统一字段

各适配器最终返回技术相关天气 Dataset。

可用字段：

| 统一字段 | 目标单位 | 用途 | 是否必需 |
|---|---|---|---|
| `temp_C` | °C | 高温、冻雨代理、低温大风、结冰 | 依事件而定 |
| `wind_ms` | m s⁻¹ | 大风、低温大风、风电低资源 | 依事件而定 |
| `precip_mmh` | mm h⁻¹ | 暴雨、冻雨代理 | 可选 |
| `rsds` | W m⁻² | 光伏低资源 | 可选 |
| `rh_pct` | % | 结冰、高湿度、高温高湿 | 可选 |
| `dust_aod` | 1 | 沙尘 | 可选 |

## 7.2 不同来源到统一字段的映射

| 来源 | 温度 | 风速 | 降水 | 辐射 | 湿度 |
|---|---|---|---|---|---|
| `regional_bcsd` | `tas` | `sqrt(uas²+vas²)` | `pr` | `rsds` | 无 |
| `china_cmfd_bcsd` | `tas` | `sfcWind` | 可选 `pr` | `rsds` | 无 |
| `cordex_nam12` | `tas` | `sqrt(uas²+vas²)` | 可选 `pr` | `rsds` | 无 |
| `era5land_raw` | `t2m` | `sqrt(u10²+v10²)` | `tp` 反累积 | `ssrd` 反累积 | `t2m+d2m` |

## 7.3 单位转换原则

### 温度

| 输入单位 | 转换 |
|---|---|
| `K`, `kelvin` | `-273.15` |
| `degC`, `°C`, `C`, `celsius` | 原值 |
| 缺失单位 | 默认报错；仅在显式开启 `--allow_unit_inference` 时允许按数量级推断 |

### 风速

| 输入单位 | 转换 |
|---|---|
| `m s-1`, `m/s` | 原值 |
| `km h-1`, `km/h` | `÷ 3.6` |
| 缺失单位 | 默认报错；显式允许时可视为 `m s-1`，但必须写日志 |

### BCSD / CORDEX 降水

目标：

```text
mm h-1
```

至少支持：

| 输入单位 | 转换 |
|---|---|
| `kg m-2 s-1` | `× 3600` |
| `mm s-1` | `× 3600` |
| `mm day-1` | `÷ 24` |
| `mm h-1` | 原值 |
| `mm` 每时间步累计 | `÷ timestep_hours`，但必须通过配置显式确认 |

禁止猜测累计语义。

### BCSD / CORDEX `rsds`

目标：

```text
W m-2
```

至少支持：

| 输入单位 | 转换 |
|---|---|
| `W m-2` | 原值 |
| `J m-2` 每时间步累计 | `÷ timestep_seconds`，但必须显式确认 |

### ERA5-Land `tp` 与 `ssrd`

ERA5-Land 不是简单单位换算，而是：

```text
先反累积，再换单位
```

# 8. 事件定义与来源适配

## 8.1 当前简单事件

现有事件模块保持不变：

### 风电

| 信号 | 条件 | 依赖字段 |
|---|---|---|
| `high_temp` | `temp_C > 35` | `temp_C` |
| `high_wind` | `wind_ms > 18` | `wind_ms` |
| `icing` | `temp_C < -2 & rh_pct >= 85` | `temp_C`, `rh_pct` |
| `hot_humid` | `temp_C > 30 & rh_pct >= 85` | `temp_C`, `rh_pct` |

### 光伏

| 信号 | 条件 | 依赖字段 |
|---|---|---|
| `freezing_rain` | `temp_C < 3 & precip_mmh > 0` | `temp_C`, `precip_mmh` |
| `rainstorm` | `precip_mmh > 2` | `precip_mmh` |
| `cold_highwind` | `temp_C < 5 & wind_ms > 8` | `temp_C`, `wind_ms` |
| `icing` | `temp_C < -2 & rh_pct >= 85` | `temp_C`, `rh_pct` |
| `high_humidity` | `rh_pct >= 95` | `rh_pct` |
| `dust` | `dust_aod > 0.5` | `dust_aod` |

注意：

```text
freezing_rain
```

是基于低温和降水的代理信号，不是完整降水相态识别。

## 8.2 缺失变量时的行为

可以复用：

```python
registry.simple_signals(tech, weather, skip_missing=True)
```

但是必须补充：

1. 日志打印跳过事件；
2. 输出属性记录：
   - `supported_events`
   - `skipped_events`
   - `skipped_event_reasons`
3. 不得为缺失变量事件伪造全零数组；
4. 如果事件在 `--require_events` 中，则缺失依赖字段时直接报错。

## 8.3 低资源事件第一阶段暂缓

现有低资源算法依赖：

- 24 小时居中滚动；
- `clim288(month, hour)`；
- 固定基线期；
- 向后扩展一个时间步；
- 光伏夜间过滤。

不同来源时间分辨率不同：

| 数据源 | 时间步长 |
|---|---:|
| `regional_bcsd` | 3 h |
| `china_cmfd_bcsd` | 3 h |
| `cordex_nam12` | 1 h |
| `era5land_raw` | 1 h |

因此第一阶段统一跳过 `low_resource`。

后续实现前必须明确：

1. 3 小时数据是否使用 8 个时间步近似 24 小时；
2. 原算法“向后扩展 1 小时”在 3 小时数据中如何定义；
3. 基线期使用 historical、ERA5-Land 还是各 SSP 自身历史段；
4. CORDEX、CMFD 与 ERA5-Land BCSD 是否使用各自基线；
5. 跨来源结果是否允许直接比较。

# 9. 不同技术使用不同内部天气时间轴

## 9.1 为什么风电与光伏不能共用一套内部天气时间轴

容量因子代码已经反映出：

- 风速、温度等瞬时变量可能标记在整点；
- 辐射、降水等时段平均量可能标记在半点；
- 光伏计算通常以 `rsds` 为目标时间轴；
- 风电计算通常以风速原始时间轴为目标时间轴。

因此，运行时应分别构造风电和光伏内部天气数据。默认情况下，这些数据只在内存或分块流式处理中存在。

只有启用：

```text
--save_weather
```

才分别落盘：

```text
weather_wind_*.nc
weather_solar_*.nc
```

## 9.2 风电天气文件

至少包含：

```text
temp_C
wind_ms
```

目标时间轴：

| 来源 | 风电目标时间轴 |
|---|---|
| `regional_bcsd` | `uas/vas` 公共时间轴 |
| `china_cmfd_bcsd` | `sfcWind` 时间轴 |
| `cordex_nam12` | `uas/vas` 公共整点时间轴 |
| `era5land_raw` | ERA5-Land 原始逐小时时间轴 |

## 9.3 光伏天气文件

至少包含可用字段：

```text
temp_C
wind_ms
precip_mmh
rsds
rh_pct
dust_aod
```

目标时间轴：

| 来源 | 光伏目标时间轴 |
|---|---|
| `regional_bcsd` | `rsds` 时间轴 |
| `china_cmfd_bcsd` | `rsds` 时间轴 |
| `cordex_nam12` | `rsds` 半点时间轴 |
| `era5land_raw` | ERA5-Land 原始逐小时时间轴 |

如果降水用于光伏事件，则要求：

```text
pr 时间轴与 solar target time 对齐
```

若不一致：

- 默认报错；
- 后续可增加显式配置；
- 不要静默取交集；
- 不要静默插值累计降水。

# 12. 代码接口建议

## 12.1 Adapter 返回值

每个 adapter 应返回统一对象，而不是在主入口中堆叠大量 `if/else`。

建议：

```python
from dataclasses import dataclass
from typing import Sequence
import xarray as xr

@dataclass
class WeatherBundle:
    source: str
    tech: str
    dataset: xr.Dataset
    spatial_dims: tuple[str, ...]
    grid_kind: str
    target_time_axis: str
    source_timestep_hours: float
    source_files: Sequence[str]
    skipped_inputs: dict[str, str]
```

其中：

```text
dataset
```

包含适用于该技术的统一天气变量。

## 12.2 Adapter 抽象接口

```python
class WeatherAdapter:
    def iter_tasks(self, args):
        ...

    def load_wind_weather(self, task) -> WeatherBundle:
        ...

    def load_solar_weather(self, task) -> WeatherBundle:
        ...
```

## 12.3 事件生成

事件模块只做阈值判断。

```python
masks = registry.simple_signals(
    tech,
    weather_dict,
    skip_missing=True,
)
```

当前简单事件模块主要是 NumPy 比较操作，因此数组维度可以是：

```text
(time, station)
(time, lat, lon)
(time, rlat, rlon)
```

不需要为了调用事件模块而强行展平空间维度。

## 12.4 写出函数

信号文件始终写出：

```python
write_signal_dataset(bundle, masks, signal_out_path)
```

天气文件仅在显式开启 `--save_weather` 时写出：

```python
if args.save_weather:
    write_weather_dataset(bundle, weather_out_path)
```

要求：

- 默认不创建 `weather/` 目录；
- 默认不写出 `weather_*.nc`；
- 临时文件写完后再 `os.replace()`；
- 已存在且可正常打开时默认跳过；
- 不完整文件自动重算；
- 信号变量使用 `int8`；
- 可选天气变量使用 `float32`；
- 保留坐标变量及属性；
- CORDEX NAM-12 保留二维 `lat/lon` 和旋转极网格属性；
- `weather_saved=true|false` 写入信号文件属性。

# 13. 时间对齐策略

## 13.1 原则

不要用一个全局 `xr.align(join="inner")` 静默裁剪所有变量。

每次对齐必须明确：

```text
target axis
source axis
变量类型
是否允许插值
是否允许边界 nearest
是否允许丢失时间步
```

## 13.2 瞬时变量

可以线性插值：

```text
tas
uas
vas
sfcWind
```

典型用途：

```text
将整点瞬时值插值到 rsds 半点时间轴
```

## 13.3 时段平均或累计变量

不要盲目线性插值：

```text
pr
rsds
tp
ssrd
```

处理原则：

| 变量 | 处理方式 |
|---|---|
| BCSD `rsds` | 作为光伏目标时间轴 |
| BCSD `pr` | 优先要求和光伏目标时间轴一致 |
| NAM-12 `rsds` | 作为光伏半点目标时间轴 |
| ERA5-Land `tp` | 原生逐小时时间轴，先反累积 |
| ERA5-Land `ssrd` | 原生逐小时时间轴，先反累积 |

## 13.4 日志与属性

每个输出文件必须记录：

```text
target_time_axis
time_alignment
interpolated_variables
non_interpolated_variables
```

- 计算失败自动删除当前不完整文件；
