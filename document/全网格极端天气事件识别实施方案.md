编写日期：2026-09-22。代码基线：`develop-patch @ 97b10d4`。

当前实施分支为 `develop-patch-grid`，已从 `develop-patch` 创建并切换。当前范围为全网格计算代码、数据存储、分块与多进程加速及本地验证。超算运行暂不纳入实施范围；后续相关目录统一为 `infos/scnet_patchify_grid/`，本阶段不创建或完善该目录，也不规划其内部文件。

结论来自当前仓库及 `ref_code/bcsd` 指向的本地上游源码；历史超算状态引用仓库运行记录，未实时登录核验。上游源码检查时为 `9d3f158`，实际数据使用前须核对生产版本。

实现状态：网格读写、基线与信号入口、时间流式计算、多进程恢复和本地测试已落地；实际命令见 [README](../README.md)，验证和小样本性能见 [实现与本地验证记录](全网格实现与本地验证记录.md)。下文第 2 节描述分叉时的场站版本，后续章节为网格实现的设计依据。

## 1. 推荐决策

1. **在已创建的 `develop-patch-grid` 分支提供独立全网格入口。** 保留事件定义和单位转换，不要求新分支兼容场站 CLI、场站输出或现有 Loss 读取器。
2. **最终文件采用 `signal_<event>(time, lat, lon)`，经纬度直接复制 BCSD final 的 patch 坐标。** 默认按 patch、技术类型、时间段分文件；首选每 5 年一份，最后一份为 2060 年。不要求一个文件覆盖全球或全部 46 年。
3. **计算分成“固定基线预计算 → 时间段信号计算”两阶段。** 每阶段内部按连续空间 tile 多进程，按时间 chunk 读取；基线、part 和最终文件均有明确的重试身份。
4. **“所有格点”首先覆盖现有 BCSD 提供气象数据的全部格点，完全取消场站筛选。** 同时保留 patch 的完整矩形网格，海洋等无输入位置写缺测。若目标包括海洋、南极洲或上游过滤掉的小岛，需要先扩展 BCSD 数据覆盖，仅改本项目不能产生这些位置的气象数据。

## 2. 分叉时的场站代码和数据逻辑

### 2.1 生产调用链

```text
infos/scnet_patchify/create_extreme_patch_jobs.py
    → 每个 model × scenario × patch × tech 一份 Slurm 脚本
    → scripts/station_signals_patchify.py
        → patch manifest 的 core_bbox_360
        → SSP 对应 stations CSV：按技术、bbox 筛选，按经纬度去重
        → BCSD 各变量 final.nc + final.nc.json
        → 参考时间轴 + nearest/bilinear 场站匹配

        → 匹配有效性 + activation_year 掩膜
```

| `registry.py`、`events/` | 普通事件阈值与低资源入口 | 复用科学判据，补充事件所需变量清单 |
| `tools/common.py` | rolling、clim288、P5、太阳高度角、t+1 标记 | 保留数值语义，支持使用已算好的 roll/anomaly |

当前 wind 读取 `tas, uas, vas, hurs, pr`，solar 再加 `rsds`。代码用 `hypot(uas, vas)` 得到 10 m 风速；wind 参考 `uas.time`，solar 参考 `rsds.time`，其他变量按线性插值对齐。新版本保持这一技术类型各自的时间基准，不能因空间网格相同就假定时间戳相同。

当前实际输出为：

```text
<output-root>/<model>/<scenario>/<patch>/<tech>.nc
signal_<event>(time, station): int8，0 / 1
station_id、lon、lat、capacity_gw、activation_year、match_dist_deg
```

`--years` 当前被硬性限制为 `2015-2060`。不能只放宽 argparse 就宣称支持分年计算：读取切片、基线选择、边界和缓存身份都要一起调整。

### 2.2 事件定义应保留哪些内容

| 技术 | 当前实际可计算事件 | 判据要点 |
|---|---|---|
| wind | icing、high_temp、hot_humid、high_wind、low_resource，共 5 个 | 普通事件逐时逐点独立；low_resource 使用风速距平 P5 |
| solar | freezing_rain、rainstorm、high_humidity、cold_highwind、icing、low_resource，共 6 个 | low_resource 使用 rsds 距平 P5，随后过滤夜间 |
| solar | dust 当前跳过 | BCSD 没有 `dust_aod`；继续记录跳过原因，不写全零伪结果 |

以可执行常量为准。例如 `events/wind_high_wind.py` 当前阈值为 **18 m/s**，文件顶部说明仍写 17 m/s；空间扩展不能顺手改变阈值。

低资源的当前执行顺序：

1. 在完整时序上做 24 小时居中滚动；3 小时数据对应 8 步，窗口必须完整。
2. 只选 2015–2024 的滚动结果，按月×小时得到每点 `clim288(12,24,K)`。
3. 每点基线距平的 `np.nanpercentile(..., 5, axis=0)` 为阈值。
4. `anom(t) <= P5`，同时标记 `t` 和 `t+1`。
5. 当前时刻距平无效则清除标记；光伏在此之后过滤夜间。

P5 是**同一格点的时间分位数**，不能替换成 patch 所有格点的空间分位数，也不能每年重新标定。不同 model、scenario、tech 的基线默认分别计算；即使日期一样，也不自动共享。

一个已确认的提速点：入口先算 `roll/clim/anom/thr`，随后 `registry.low_resource_signal → common.low_resource` 再算一次 `roll/anom`。README 所说“只算一次 rolling”与当前实际调用链不完全一致，改造应以代码为准。

## 3. 全网格 NetCDF 契约

### 3.1 文件布局

建议使用独立输出根 `extreme_grid/<run-version>/`：

```text
<root>/<model>/<scenario>/<patch>/<tech>/
    baseline_2015-2024.nc
    baseline_2015-2024.nc.json
    signals_2015-2019.nc
    signals_2015-2019.nc.json
    signals_2015-2019.nc.timing.json
    ...
    signals_2055-2059.nc
    signals_2060-2060.nc
    manifest.json
```

`manifest.json` 列出预期时间段、已完成文件、实际时间数量、坐标指纹和事件列表。各时间段 worker 只发布自己的 sidecar；父级清单由单独汇总步骤原子更新，避免多个作业同时覆盖。

每个 signals 文件：

```text
dimensions: time, lat, lon
time(time): 参考变量对应时段的原始数值编码、units、calendar
lat(lat), lon(lon): BCSD final 原始坐标值、dtype、顺序
domain_mask(lat, lon): 1=上游计算域，0=域外
signal_<event>(time, lat, lon): int8
```

输出事件编码：

- `0`：该事件可判定且未发生。
- `1`：该事件可判定且发生。
- `_FillValue=-127`：域外，或该事件所需输入/基线/窗口无效。
- `flag_values` 写成 `int8 [0,1]`，`flag_meanings="no_event event"`；补齐经纬度 units、standard_name 等元数据。

不能把 `_FillValue` 设为 0；否则 xarray 解码会将“无事件”当缺测。默认解码后 int8 可能表现为带 NaN 的浮点数组，验收原始类型与编码应使用关闭 mask/scale 的读取方式。

缺测判断按**事件所需变量**进行。例如 high_temp 只依赖 tas，pr 缺测不应使它无效。普通事件条件即使因 NaN 比较得到 False，也不能直接当作有效的 0；由写出层应用显式有效性掩膜。low_resource 需要当前完整窗口、对应 climatology 和有限 P5；光伏夜间且输入有效写 0，输入无效仍写缺测。

这是全网格输出对缺测的明确区分。与旧场站输出比较时，在双方有效位置要求信号逐位相等；旧输出把缺测写 0 的位置单独检查有效性编码。

基线文件保存：

```text
clim288(month=12, hour=24, lat, lon): float32
p5(lat, lon): 与原始 percentile 计算一致的精度，默认 float64
baseline_valid_count(lat, lon): int32
domain_mask(lat, lon)
```

`clim288` 保留原有 12×24 索引语义；3 小时时间轴只占用部分 hour 槽，其他槽为缺测。时间分钟信息保留在参考时间轴及元数据中，不能擅自改成整点。P5 写成 float64 是为避免阈值量化改变边界信号。

基线和信号都记录 `schema_version`、code SHA、事件判据、输入清单/上游身份、grid/mask/time fingerprint、参考变量、基线期、窗口及 t+1 规则、calendar、缺测策略、跳过事件。基线缓存身份还包含 `_pseudo` 时间映射和 percentile 方法版本。

### 3.2 “和输入网格一致”的验收含义

1. 同 patch 的所有输入变量经纬度一致后才按索引读取；不一致时报告输入冲突，不静默重采样。
2. 输出经纬度数组与 BCSD 参考 final 完全相等；不重建 `arange`、不四舍五入、不转换经度范围、不随意升降序。
3. 北极所在 patch 可能为 301×300，其余常见 300×300，均从文件读取，不写死形状。
4. 只输出 final 的 core 网格，不重复加入 BCSD 工作区 3° buffer。
5. 时间轴以技术对应参考变量的原始 calendar 截取；保留 `365_day` 等非 Gregorian 编码，不用 pandas 强行转换为公历。
6. 若需要全球视图，后续依据 land plan 的全局索引拼接，检查覆盖和重复格点；缺失 patch 保留缺测。日常分析按 manifest 选时段/patch 读取即可，不把全球单文件拼接列为本次生产前置条件。

### 3.3 体量和分文件原因

按 no-leap 估算，2015–2060 共 `T=46×365×8=134,320` 个时次；其他 calendar 用真实长度。

| 范围 | 未压缩事件数组逻辑体量，十进制 GB/TB |
|---|---:|
| 300×300 patch，46 年，wind 5 事件 | 60.44 GB |
| 同 patch，46 年，solar 6 事件 | 72.53 GB |
| 同 patch，5 年，solar 6 事件 | 7.88 GB |
| 47 patch × 12 个 model/scenario 组合 × 两技术，按每 patch 300×300 近似 | 75.00 TB |
| 仅按历史 1,526,295 个陆地点估算上述全矩阵 | 27.06 TB |

矩形数值是逻辑大小，实际磁盘量取决于稀疏未写 chunk、有效域比例、压缩和事件分布；不要承诺固定压缩比。北极额外一行、闰年、元数据和 chunk 开销会增加体量。投产前还要计入 parts 与 final 同时存在、失败尝试、阈值缓存的峰值空间和 inode。

写出默认保留 NetCDF4 + zlib，试验 level 1/2/4，chunk 起点用 `(240,64,64)` 或与 tile 对齐的尺寸；均裁剪到实际维度。纯域外 tile 不执行科学计算，并保持未写 fill chunk，仍在覆盖清单中记为已处理域外区域。

## 4. 计算与加速设计

### 4.1 连续空间 tile + 时间 chunk

不把全网格伪装成百万行 stations CSV。直接：

```text
输入变量[源时间切片, y0:y1, x0:x1]
    → 时间对齐、单位转换
    → 临时 reshape 为 (T_chunk, K)，K=tile_y×tile_x
    → 复用 events/ 中的数组判定
    → reshape 回 (T_chunk, tile_y, tile_x)
    → 写 tile part
```

这个内部 K 只是局部数组布局，最终文件没有 station/point 维。事件均为逐点算法，不需要空间 halo；只有时间窗口需要 halo。

初始试验空间 tile 为 16×16、32×32、64×64，信号时间 chunk 为 240/480/960；优先保证内存，再考虑与 BCSD 压缩 chunk 对齐。小 tile 会造成同一输入 chunk 被不同进程重复解压，64×64 则能减少这种重复，但基线内存更高。

必须保留连续 slice 读取。现有项目曾因散列 lat/lon 索引在压缩文件中重复解压而长时间无进展；不能因点集压缩而回退到同类磁盘散读。

### 4.2 阶段 A：每个 patch/tech 计算一次基线

输入：同 model/scenario/patch 的 BCSD 资源变量、land plan、参考时间轴。wind 只需 uas/vas；solar 只需 rsds。

每个 tile worker：

1. 在完整输入时间轴上定位 2015–2024 的中心时刻，读取所需资源及边界 halo。
2. 计算滚动，截取中心位于基线期的值；构建 clim288，再计算基线距平和精确 P5。
3. 保持 `np.nanpercentile` 的算法和精度，不把各年的 P5 再求平均，也不默认改为近似分位数。
4. 写独立基线 tile part；父进程按空间块合并 `baseline_2015-2024.nc`，校验后发布 sidecar。

基线只缓存 resource/rolling/anomaly 必要数组，不同时保留六个气象变量。可在空间子块上精确算 P5，不需要一次装下整个 patch。

注意 2024 年末的居中窗口需要 2025 年开头的数据：只读取 2015–2024 文件范围再 rolling 会与当前全时序算法不同。2015 年初则以现有完整计算区间的真实起点为边界，不引入当前方案未使用的 2014 年数据来填窗口。

### 4.3 阶段 B：按时间段生成全网格信号

默认输出时间段：2015–2019、2020–2024、…、2055–2059、2060–2060。时间段长度由参数控制，输出名和身份按实际起止年生成。

每个 tile worker：

1. 打开输入文件及本 tile 对应基线，预先建立各变量到参考时间的插值索引与权重。
2. 按带 halo 的时间 chunk 读取天气，执行现有单位转换与普通事件判定。
3. 每 chunk 只算一次资源 roll/anomaly，使用已固定 clim288/P5 判定低资源。
4. 先执行 t+1 扩展，再应用当前时刻有效性和光伏夜间过滤；只写 chunk 的中心区间。
5. 输出独立 tile part，父进程逐事件×时间 chunk×空间 tile 合并为该时段 NetCDF。

时间索引必须按实际源时间搜索，不能沿用“目标位置 s0 在源文件也是 s0”的假设。禁止外推；需要的源时间不存在则保留缺测。对原始 CF 时间轴检查单调、步长和 calendar，索引构建后在同作业内复用。

### 4.4 跨 chunk / 跨年边界必须准确

当前 pandas `rolling(8, center=True)` 在时刻 `i` 使用资源 `[i-4, i+3]`。本次已用本地实际依赖验证该窗口位置。

对输出半开区间 `[a,b)`：

- 计算中心时刻的原始事件需要 `[a-4,b+3)`。
- 加上 `ev(a-1)` 对 `a` 的 t+1 影响，需要资源范围 **`[a-5,b+3)`**，即左侧 5 步、右侧 3 步。
- 源变量时间插值还需各自左右源样本，使用源时间索引另外扩展；它与 rolling halo 是两层不同的边界。
- 在完整 2015–2060 区间的首尾裁剪，不把内部 chunk 边界当作全时序边界；首尾不足完整窗口保留无效。
- solar 的 `ev(a-1)` 是夜间过滤前的原始事件，不能先过滤前一步夜间再传播，否则改变跨日出时刻的结果。

当前 `_pseudo` 把月/日/时映射到 2000 年供月×小时和太阳高度角计算；这会影响年内日序。首版保留该行为以隔离空间扩展，不同时修改太阳几何算法。输出时间仍使用真实原始时间；不得对重复的伪年份索引执行“全局单调”检查。

### 4.5 内存预算

旧流程仍把一个 station block 的完整 46 年各变量存入内存。如果改成 64×64 tile 后直接照搬，六个 float32 原始数组就约 **12.30 GiB/worker**，尚未计入滚动、距平、太阳角度及临时数组。

新流程分开估计：

```text
基线单资源数组：T_baseline × K × 4 bytes
信号阶段原始天气：T_chunk × K × N_weather × 4 bytes
作业峰值：worker 数 × 实测单 worker 峰值 + 父进程/写入/cache
```

例如 64×64 tile：10 年单资源数组约 0.446 GiB；240 步、六个 float32 数组约 22.5 MiB。基线多个副本、pandas rolling 的 float64 中间量、太阳高度角的多个 float64 数组仍可能显著增加峰值，因此以上只是原始数组下界。

父进程必须按 `time_chunk × tile_y × tile_x` 复制，不创建 `time_chunk × 全 patch` 或全全球缓冲。现有 `_merge_parts` 的 `np.empty((4096,total_stations))` 和一次打开全部 parts 的模式需要替换；使用有限文件句柄缓存或逐 part 打开。

### 4.6 加速优先级

| 优先级 | 方案 | 收益与限制 |
|---|---|---|
| P0 | 去掉场站匹配，连续 tile 读取 | 避免索引计算及不规则散读；全网格总读取量仍会上升 |
| P0 | 基线一次计算、时间 chunk 流式信号 | 控制内存，允许时间段独立重试和并行 |
| P0 | 消除重复 roll/anomaly | 当前已有明确重复计算，不改变科学定义 |
| P0 | spawn 多进程，每 worker 自己打开输入和 part | 延续已验证模式；禁止多个 worker 并写同一 NetCDF |
| P1 | 输入 chunk 对齐、压缩级别、缓存预算 | 降低重复解压和写出尾部；缓存需乘进程数计入内存 |
| P1 | 预计算时间索引、月小时组和太阳几何公共时间项 | 减少重复 xarray 插值对象及三角函数计算；必须验证数值等价 |
| P1 | wind 阶段 B 不再读取 pr | 当前 wind 事件不使用降水；以 registry 显式变量依赖驱动 |
| P2 | clim288 sum/count 聚合、rolling 专门实现 | 只有 profiler 显示热点且等价测试通过再做；浮点求和顺序可能改变阈值边缘 |
| P2 | 直接读取上游 `(time,point)` block | 可减少海洋解压；需对齐 land plan、全局索引、时间边界和 block manifest，独立评估 |

首版保留 wind/solar 分开计算，因为参考时间轴不同。共享读取不一定安全，不能只因它们读取相同变量就合并天气数组。现有 NumPy/pandas/xarray/netCDF4 足以实现首版，不新增 Dask、GPU 或存储格式依赖。

## 5. 计算分片与产物契约

| 内容 | 阶段 A：baseline | 阶段 B：signals |
|---|---|---|
| 分片身份 | `grid/baseline/<model>/<scenario>/<tech>/<patch>/2015-2024` | `grid/signals/<model>/<scenario>/<tech>/<patch>/<start>-<end>` |
| 输入依赖 | 资源变量 final + sidecar、land plan | 所需天气 final + sidecar、同身份 baseline 完成 |
| 进程内/进程间分块 | 空间 tile | 空间 tile；tile 内按时间 chunk 流式 |
| 预期产物 | baseline.nc + sidecar | signals.nc + sidecar + timing |
| 重试范围 | 未完成或身份不一致的基线 tile | 未完成或身份不一致的信号 tile |
| 完成条件 | 所有 tile 覆盖，文件及 sidecar 通过契约校验 | 同左，并且时间范围及 baseline fingerprint 一致 |

同一次运行内用运行标识/配置指纹区分输出身份。part 路径至少绑定 stage、model、scenario、patch、tech、时间段、tile bounds 和配置指纹；sidecar 保存上述身份、输入版本及状态。

发布顺序为 `独有临时文件 → 关闭并校验 → 原子 rename NC → 原子发布 sidecar`，两文件之间发生中断时归类为不完整；重试按契约补齐或重算。`--overwrite` 不能绕过输入/基线/part 身份检查，不得因为旧文件存在就判完成。

信号计算入口检查对应基线已完成且身份一致。每个输出文件只由一个写入者发布；本阶段验证直接运行计算入口及其多进程路径，不依赖调度系统。

若沿用历史完整矩阵和 5 年分段：

- baseline：1,128 个计算分片。
- signals：每组合 10 段，共 11,280 个计算分片。
- 合计 12,408 个计算分片，不包含可选全球拼接。

上述数量描述计算和产物划分，不预设超算作业数量或提交粒度。当前先完成计算入口、数据依赖、内存控制、结果校验和断点恢复。

## 8. 测试与验收

### 8.1 科学和格式正确性

1. **网格中心对照**：在小网格每个有效中心放一个虚拟测试站，activation_year 不晚于 2015、nearest 精确命中；新网格结果在有效域与旧算法逐位一致。bilinear 场站结果不作为原生格点的相等标准。
2. **时间分块等价**：整段与多个 chunk/多个年份段拼接一致；专门覆盖跨年、基线 2024/2025 边界、首尾不足窗口、NaN 窗口及 t+1 跨块传播。
3. **日历与偏移**：Gregorian 闰年、365_day、90 分钟偏移、参考变量起止时刻不同；检查实际时间坐标及不外推行为。若发现其他 calendar，先明确适配规则再加入支持列表。
4. **事件边界**：阈值相等、浮点临界点、NaN/Inf、climatology 槽无样本、全 NaN 基线；分位数前排除非有限值的行为与当前一致。
5. **太阳规则**：日出/日落、极昼/极夜、夜间原始事件传播到下一时刻后再过滤；经度 `[0,360)` 不因站点规范化改变。
6. **坐标和覆盖**：升降序测试夹具、0/360 附近、北极额外行、最后一个不完整 tile、相邻 patch core 不重叠；逐坐标与输入相等。
7. **缺测**：海洋/域外保持 fill；事件相关输入缺测不写有效 0；有效无事件格点不会被 xarray 解码成缺测；dust 缺输入不写伪信号。
8. **并行/恢复**：1/2/4 worker 与不同 tile 尺寸一致；缺 sidecar、缺 part、中断 merge、改年份、改输入版本、改 tile 布局时遵循预期重算逻辑。
9. **计算入口与依赖**：两个入口的参数校验、输出身份和错误提示符合契约；缺失或身份不一致的基线不能用于 signals；直接运行入口可完成小样本端到端验证。

保留单位转换测试。测试仅收集当前项目 `tests/`，不把 `ref_code` 内历史项目测试一起运行。

### 8.2 本地基准测试

使用合成数据和本地可用的代表性小样本，覆盖陆地点较密、海岸/稀疏、北极/日历边界及 wind/solar。样本包含验证完整基线语义所需的时间范围，空间规模按本机资源限制。

- processes：从 1/2/4 开始，按本机 CPU 和内存决定是否增加。
- tile：16×16、32×32、64×64；先筛选，再对合适组合调 time chunk 和压缩，避免穷举所有组合。
- 记录 baseline、天气读取/插值、普通事件、低资源、part 写入、merge 各阶段时间，以及父进程和 worker 的峰值内存、读写量、输出和临时空间峰值。
- 比较指标用“每秒有效格点×时次”和“完整计算分片墙钟时间”，不能只看 worker 计算时间。
- 进程数、tile 和 time chunk 必须受本机资源约束；本地小样本性能不用于承诺全量超算耗时。

当前验收目标是科学结果一致、内存随分块受控，并具备可测量的读取、计算和写出性能。超算资源配置和批量运行验证留待后续单独规划。
